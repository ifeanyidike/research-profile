M03
Modular arithmetic keeps the remainder after division. It appears in number systems and cryptography, where exact mathematical rules matter.
Work with remainders under a stated modulus. Check whether inverses exist, and state the assumptions behind any count of possible choices.
Compute 5×3 mod 7 = 1, so 3 is an inverse of 5 modulo 7. Compare this with 2 modulo 6: multiplying 2 by any integer cannot produce a remainder of 1. List the possible remainders to see why. Then count four-digit strings with and without repeated digits, explaining why the formulas differ.
Ordinary division cannot simply be copied into modular arithmetic. An inverse may not exist.
Does 2 have a multiplicative inverse modulo 6?
No, because 2 and 6 are not coprime
Yes, every nonzero number has one for every modulus
Yes, its inverse is the decimal number 0.5
An inverse must be an integer residue whose product is 1 modulo 6. None exists because gcd(2,6)=2.

M04
A security alert is evidence, not certainty. Probability helps combine how common an event is with how often a detector raises or misses an alert.
Turn rates into counts, keep conditional questions distinct and check independence. Uncertainty depends on how choices or observations were produced.

Of the 189 alerts, 90 are true positives, so precision is 90/189, approximately 47.6%. Recall asks about all 100 malicious events instead: 90/100=90%. Check each denominator and explain how the answer changes if the base rate changes.
A detector's sensitivity is not its precision. Both depend on which population and threshold are being measured.

90 percent
99 percent
The current worked table has 90 true alerts and 99 false alerts. All alerts total 189, so precision is 90/189, about 47.6%. The 90% recall answers a different question.

C01

C04
A pointer refers to a location in memory. Correct code must know whether that location is valid, who owns the data and how long the data remains available.
For each pointer, check the target, bounds, lifetime and owner. Draw changes to those facts as execution proceeds.
On paper, draw node A at illustrative address 100 and node B at illustrative address 200. A stores value 10 and next=200; B stores value 20 and next=null. Start head=100. Save A’s next address before freeing A, move to B, save its null next, then free B and set head=null. Mark each object unavailable immediately after its free. These addresses are invented; do not enter them into a program.
Setting one pointer to null does not invalidate other aliases that still point to the released object.
Why is dereferencing an old alias unsafe after its allocation is freed?
The object's lifetime has ended even if the address value remains
Free automatically updates every alias to null
Heap addresses are always immediately erased
The pointer value can outlive the object. Access through it is invalid regardless of whether bytes still appear unchanged.

C07

Then protect the check and update together, so the second operation sees balance=3 and fails. Explain the invariant: accepted withdrawals must not make the balance negative.
A sleep changes timing but does not establish synchronisation. A race disappearing during debugging may still exist.

Only printing the receipt
Only reading the account's display name
