ID:: V01
BRIDGE:: You do not need to code yet. Imagine that you are designing an assistant that helps someone book an appointment. Follow one request from the microphone to the reply.
CONCEPT:: A voice assistant has several jobs to do. It must receive sound, work out what you said, decide what to do, and speak a reply. Understanding these jobs will help you find the cause when something goes wrong.
MECHANISM:: Follow the information through the system: recorded sound → recognised words → a decision → any approved tool action → a spoken reply. Check each handover when a request fails.
TEACHING:: ### Follow one request

You say, “Book a meeting with Ada on Friday.” The microphone turns the sound into an electrical signal. Recording software stores measurements of that signal as numbers. We will look closely at those numbers in the sound lessons.

A speech recogniser turns the recording into written words. Its technical name is automatic speech recognition, or ASR. Here its output might be the text “Book a meeting with Ada on Friday.” It can mishear a name, so the next part must be able to ask you to correct it.

### Decide what the words mean

The assistant needs more than a transcript. Which Friday do you mean? What time? Which Ada? The conversation manager keeps track of the information you have given and asks for anything still missing. A language model can help with these messages, but the application must still check the details.

When the details are ready, a calendar tool can create the meeting. A tool is a function that the application can call. Permission to understand a request is different from permission to change a calendar. The application should show the proposed details and get the approval its booking policy requires before it creates anything.

### Turn the answer back into sound

The assistant might reply, “The meeting is booked for Friday at ten.” Text-to-speech, or TTS, turns those written words into audio. The application sends the audio to the speaker. Sending sound between devices is another job, called transport.

If the reply is wrong, ask where the mistake first appeared. Was the name wrong in the transcript? Were the right words interpreted incorrectly? Did the calendar reject the request? Breaking the system into jobs gives you somewhere concrete to look.
EXAMPLE:: Fictional task: reschedule a rehearsal.
User audio → ASR: “Move rehearsal to Friday.”
Dialogue: Friday is ambiguous; ask for date and time.
Tool proposal: change event 17 to Friday, 14:00.
Application: validate account, event ownership and explicit confirmation.
TTS: “Please confirm Friday at two.”
Only after confirmation: apply one uniquely identified change.
EXPLANATION:: ASR does not grant calendar permission. The dialogue cannot safely guess which Friday. The tool layer must distinguish proposing an action from committing it. A response can sound fluent while the system is still missing essential information.
PITFALL:: A fluent reply can still describe an action that never happened. Check the calendar result before telling the user that a meeting was created.
EXERCISE:: On paper, map a fictional library telephone assistant. It may read opening hours and propose a book reservation. Draw six boxes: capture, ASR, dialogue, reservation tool, TTS and transport. Give each box one input, one output and one possible failure. Mark the point where a user must approve a reservation. Use fictional details for this first design.
SOLUTION:: Capture supplies samples and may lose microphone access. ASR supplies candidate words and may confuse titles. Dialogue asks a clarifying question. The tool checks membership and availability before committing. TTS supplies speech but may mispronounce a title. Transport may disconnect. Confirmation belongs immediately before the authorised reservation write, with duplicate prevention at the tool boundary.
CHALLENGE:: Design the same map for a museum information kiosk that must never change bookings. Identify two components you can simplify, two failures that remain, and the evidence needed before claiming it works for visitors with different accents.
CHALLENGE_SOLUTION:: Remove booking writes and their confirmation workflow; retain a read-only information source. Recognition errors, stale opening hours and inaccessible audio still matter. A justified claim needs representative, consented task evidence and accessible alternatives, rather than one successful demonstration. A paper design alone cannot establish product performance.
QUESTION:: Which component should enforce permission to change a booking?
CORRECT:: The application and tool boundary, using the signed-in user's authority and validated action.
WRONG1:: The ASR component, because it heard a clear request.
WRONG2:: The TTS component, because it can announce the change.
FEEDBACK:: Recognising or saying an instruction does not authorise it. The component that changes state must validate permission and the intended action.

ID:: V02
BRIDGE:: You can run the example in this page. Choose Edit code to change it, then Run Python. The studio saves your edits for the active learner. If Python is familiar, this refresher is optional.
CONCEPT:: A function is a named set of instructions that you can reuse. We will write one that calculates the length of a recording, then use its answer in another calculation.
MECHANISM:: Write the calculation once inside a function. Pass values into it, reject inputs you cannot use, and return an answer that the rest of the program can work with.
TEACHING:: ### Start with the question we want to answer

Suppose a recording contains 32,000 measurements of sound. Each measurement is called a sample. The recording stores 16,000 samples for every second. How many seconds does the whole recording last?

Divide 32,000 by 16,000. The answer is two seconds. You do not need to understand recording technology to follow this calculation: if one second uses 16,000 samples, two seconds use twice as many.

### Give the calculation a name

The line starting with def creates a function called duration_seconds. The names samples and rate are its parameters: the inputs it needs. Calling duration_seconds(32000, 16000) supplies values for those inputs.

Python uses indentation to show which instructions belong to the function. The line return samples / rate divides the two inputs and sends the answer back to the code that called the function. The / symbol means divide.

### Check the inputs before dividing

A negative number of samples does not make sense here. A rate of zero would also make division impossible. The if statement checks for those cases. The word or means that either invalid condition is enough to stop the calculation.

raise ValueError reports the problem. This is an exception: a way for Python to tell the calling code that it could not finish normally. Try an invalid call separately so you can see the error.

### Keep calculating and displaying separate

return gives a value back to your program. print shows a value on screen. Keeping them separate means you can save the returned duration in seconds, multiply it by 1,000, or compare it with another duration. A function that only prints a number does not automatically return that number.

In the example, = saves a value under a name. Later, == will ask whether two values are equal. Those two symbols do different jobs.
EXAMPLE:: # Run here, or save as duration.py for Python 3.
def duration_seconds(samples, rate):
    if samples < 0 or rate <= 0:
        raise ValueError(
            "Expected non-negative samples and positive rate"
        )
    return samples / rate

seconds = duration_seconds(32000, 16000)
print(seconds)                 # 2.0
print(duration_seconds(0, 16000))  # 0.0
EXPLANATION:: The first call divides 32,000 by 16,000, giving two seconds. The second has no samples, so its duration is zero. Replacing return with print would display a number but return None; the caller could no longer safely use the duration in a calculation.
PITFALL:: Variable names do not enforce units or types. A variable called rate can still contain the string “fast”. Clear names help people, but validation and tests establish behaviour.
EXERCISE:: Predict both printed values before running the example. Add calls for 8,000 samples at 16,000 samples/second and 48,000 at 48,000. Write the expected result and unit for each. Then call the function with rate zero and explain the exception. Finally write milliseconds(samples, rate), reusing duration_seconds and multiplying by 1,000.
SOLUTION:: The original prints are 2.0 and 0.0 seconds; the added durations are 0.5 and 1.0 seconds. Define the reusable conversion after duration_seconds:

```python id=milliseconds
def milliseconds(samples, rate):
    return duration_seconds(samples, rate) * 1000

print(milliseconds(8000, 16000))  # 500.0
```

A rate of zero raises ValueError before division. Run that invalid call last or separately, because an uncaught exception stops the file. Return supplies a value to the caller; print only displays it.
CHALLENGE:: Without copying the function body, write remaining_seconds(total_samples, consumed_samples, rate). Reject consumed counts below zero or above the total. Demonstrate 32,000 total and 8,000 consumed at 16,000/second, plus one rejected case.
CHALLENGE_SOLUTION:: Add the following below duration_seconds. The supplied contract is ordinary numeric counts/rate; it does not accept text or establish a complete type schema.

```python id=remaining-seconds
def remaining_seconds(total_samples, consumed_samples, rate):
    if consumed_samples < 0 or consumed_samples > total_samples:
        raise ValueError("consumed count is outside the total")
    return duration_seconds(total_samples - consumed_samples, rate)

print(remaining_seconds(32000, 8000, 16000))  # 1.5
# Run separately as a rejected case:
# remaining_seconds(32000, 40000, 16000)
```

The rejected call asks to consume more than exists. The reused function also rejects an invalid rate.
QUESTION:: Why return a duration instead of only printing it?
CORRECT:: The caller can use the returned value in another calculation or test.
WRONG1:: Printing changes a string permanently into a number.
WRONG2:: A printed number automatically becomes every function's return value.
FEEDBACK:: Return connects functions through values. Print writes to an output stream and does not replace a useful return contract.

ID:: V03
BRIDGE:: V02 introduced functions and returned values. Here a recording is described by a short list of events. You can follow the list by hand before running any code.
CONCEPT:: A loop repeats instructions for each item in a collection. We will use a loop to add up the parts of a recording that contain speech.
MECHANISM:: A loop visits the events. A condition chooses where each event belongs. Running totals keep the results, and a final sum checks that no duration disappeared.
TEACHING:: ### Read one event first

An event is one labelled part of a recording. For example, {"kind": "speech", "duration_ms": 120} says that speech lasted 120 milliseconds. A millisecond is one thousandth of a second. The braces hold a dictionary: a set of names and their values.

A list holds several events in order. The program must read each event because some parts contain speech and others contain silence.

### Keep a running total

Start the speech total at zero. Read the first event. If its kind is speech, add its duration to the total. If its kind is silence, leave the speech total alone. Move to the next event and repeat.

For durations 120 ms of speech, 50 ms of silence and 80 ms of speech, the speech total changes from 0 to 120, stays at 120, then becomes 200. The whole recording is 250 ms long. Only 200 ms of it is labelled speech.

### See how the Python follows those steps

The for statement selects one event at a time. The if statement decides whether that event belongs in the speech total. A running total is often called an accumulator. The name sounds technical, but its job is simply to keep the sum so far.

An empty list has no events to visit, so the function returns its starting total: zero. A missing dictionary key is a different problem. The program asked for information that the event did not supply. The next lesson shows how to check the shape of data before calculating with it.

### Account for every part

In the harder exercise, keep separate totals for speech, silence and other event kinds. Do not quietly drop an unfamiliar kind. Check that the three totals add up to the duration of all events. That check helps you catch a branch that forgot to count something.
EXAMPLE:: def speech_ms(events):
    total = 0
    for event in events:
        duration = event["duration_ms"]
        if duration < 0:
            raise ValueError("Negative duration")
        if event["kind"] == "speech":
            total += duration
    return total

events = [
    {"kind": "speech", "duration_ms": 120},
    {"kind": "silence", "duration_ms": 50},
    {"kind": "speech", "duration_ms": 80},
]
print(speech_ms(events))  # 200
EXPLANATION:: The running total is 120, then 120, then 200. The complete timeline lasts 250 milliseconds, but labelled speech occupies 200. Those are different quantities. An empty list returns zero because the loop never changes the accumulator.
PITFALL:: Counting events is different from adding durations. Three short events can occupy less time than one long event. Similarly, a label named speech is supplied evidence, not proof of a detector's accuracy.
EXERCISE:: Make a table with event index, kind, duration and running speech total. Add a silence event lasting 300 milliseconds and predict both speech time and total timeline time. Then replace the first duration with -1 and explain where execution stops. Write a second function that totals all event durations.

### Build or inspect it

Write and run your bucket function. Keep the supplied event data in a separate variable. Add an empty-list case, an all-silence case and a negative-duration case. Predict the output before running each case.
SOLUTION:: The extra silence leaves speech time at 200 ms and raises total timeline time from 250 to 550 ms. A negative first duration raises before any later event. This total-duration function retains the same numeric contract:

```python id=total-duration
def total_ms(events):
    total = 0
    for event in events:
        duration = event["duration_ms"]
        if duration < 0:
            raise ValueError("Negative duration")
        total += duration
    return total
```

Calling total_ms([]) returns 0 because the loop has no iterations. The label kind does not affect this total.

### Practical check

The empty list totals zero in every bucket. All-silence data leaves speech_ms at zero. A negative duration must raise the documented error rather than reduce a total.
CHALLENGE:: Implement a summary returning a dictionary with speech_ms, silence_ms and other_ms. Treat unknown kinds as other rather than silently discarding their time. For speech 40, silence 20 and music 30, supply the expected dictionary and total-duration invariant.
CHALLENGE_SOLUTION:: A complete reference using the supplied valid event shape is:

```python id=event-summary
def summary(events):
    totals = {"speech_ms": 0, "silence_ms": 0, "other_ms": 0}
    for event in events:
        duration = event["duration_ms"]
        if duration < 0:
            raise ValueError("Negative duration")
        if event["kind"] == "speech":
            key = "speech_ms"
        elif event["kind"] == "silence":
            key = "silence_ms"
        else:
            key = "other_ms"
        totals[key] += duration
    return totals
```

For speech 40, silence 20 and music 30, the result is {"speech_ms":40,"silence_ms":20,"other_ms":30}. Their sum is 90, equal to all supplied durations. This checks dropped time, not label accuracy.
QUESTION:: What does the speech_ms function establish?
CORRECT:: The summed duration of events already labelled speech under its input contract.
WRONG1:: Whether each event really contains human speech.
WRONG2:: The number of words spoken in the audio.
FEEDBACK:: The function performs arithmetic on supplied labels. Detecting speech and recognising words are separate responsibilities.

ID:: V04
BRIDGE:: You have used a function, a loop and dictionaries. The browser example supplies events.json for you. If you run it on your computer, save the file beside the program.
CONCEPT:: A program should check the data it reads before using it. We will open a small JSON file, check that its contents have the expected shape, and test the calculation with known answers.
MECHANISM:: Read the file, check its contents, then calculate. Test the calculation with small inputs whose answers you already know. Treat a broken input differently from a valid empty list.
TEACHING:: ### Separate reading from calculating

A file lets you keep data after a program stops. JSON is a text format for lists, objects, numbers and other simple values. Python can read JSON, but successfully reading it only proves that the text follows JSON rules. It does not prove that the data is suitable for your function.

For example, both a list of events and a single number can be valid JSON. A function that expects a list should reject the single number with an explanation.

### Check the structure one step at a time

First ask whether the top-level value is a list. Then check whether each item is a dictionary. Next check that duration_ms is present. Finally check that its value is a non-negative integer.

An integer is a whole number, such as 20. A value such as 2.5, the text "20", or a missing key needs a deliberate decision. The exercise rejects them instead of guessing what the author meant. Python also treats True like an integer in some checks. Using type(value) is int deliberately excludes it here.

### Use small tests with known answers

A test compares what your code returns with what you expect. If the two durations are 20 and 35 ms, calculate 55 ms by hand first. Then check that the function returns 55. Also test an empty list and invalid inputs.

Keep these tests separate from opening the file. That lets you find out whether a failure came from the file path, JSON reading, validation or arithmetic. A module is simply a Python file whose functions another file can import and reuse.

### Make errors useful

A clear error says what input was unacceptable. Catch an error only where you can respond sensibly, such as showing a message to the learner. Catching every error and returning zero would make a broken input look like a valid zero-length recording.
EXAMPLE:: import json

def total_ms(events):
    result = 0
    for event in events:
        value = event["duration_ms"]
        if type(value) is not int or value < 0:
            raise ValueError(
                "duration_ms must be a non-negative integer"
            )
        result += value
    return result

data = json.loads('[{"duration_ms": 20}, {"duration_ms": 35}]')
assert total_ms(data) == 55
assert total_ms([]) == 0
assert total_ms([{"duration_ms": 20}, {"duration_ms": 35}]) == 55
try:
    total_ms([{"duration_ms": -1}])
except ValueError:
    pass
else:
    raise AssertionError("Negative duration was accepted")
EXPLANATION:: The function rejects negative integers, floats, strings and booleans. Python treats bool as a subclass of int, so checking type(value) is int deliberately excludes True. Missing keys still raise KeyError, an explicit limit of this introductory contract. No speech model is loaded or assessed.
PITFALL:: A program passing three tests is not proven correct for every input. A broad exception handler that returns a success-shaped result can hide failures even from an apparently tidy test suite.
EXERCISE:: Save the example as checks.py and run it with Python 3. Predict what happens for duration_ms equal to 0, 2.5, true in JSON and a missing key. Add tests for all four cases. Write events.json containing the valid two-event array, then read it with a with open(..., encoding="utf-8") block and json.load.
SOLUTION:: Zero is accepted; 2.5 and JSON true (Python True) raise ValueError. A missing key raises KeyError in the introductory version. Save the exact text [{"duration_ms":20},{"duration_ms":35}] in events.json, then add:

```python id=read-json

    saved = json.load(f)

```

Inside the studio, a fresh events.json fixture with durations 20 and 35 is supplied for each run. In your own editor, put the file in your working folder. A missing file is a file-access failure; malformed JSON is a decoding failure; a bad duration is an application-contract failure. Assertions passing normally produce no output.
CHALLENGE:: Extend validation to reject a top-level object, a non-object list item and a missing duration key with clear ValueError messages. Supply one valid and three invalid fixtures. Keep file access outside total_ms.
CHALLENGE_SOLUTION:: Keep file access outside the function. One complete stricter version and its supplied checks are:

```python id=validate-events

        raise ValueError("events must be a list")
```

These three bad fixtures all decode as valid Python/JSON-shaped values; their application shapes are wrong. Additional accepted-field policy is outside this small contract.
QUESTION:: Does successful JSON decoding guarantee a valid event list?
CORRECT:: No. The decoded value must still satisfy the application's structure and value constraints.
WRONG1:: Yes. JSON automatically checks every application-specific field.
WRONG2:: Yes, provided the JSON contains at least one number.
FEEDBACK:: JSON validates a representation. Your application separately defines the event schema and its meaning.

ID:: V06
BRIDGE:: You have seen samples, channels and bit depth in V12. Here we use those ideas in a calculation. You can use a calculator; the aim is to understand each step.
CONCEPT:: Audio calculations become easier when you write what each number means. We will start with recording length and file size, then explain the powers and logarithms used in audio measurements.
MECHANISM:: Write units first, calculate one step at a time, then check whether the answer has the unit you wanted. Powers count repeated multiplication; logarithms work backwards to the exponent.
TEACHING:: ### Keep the unit beside the number

“16,000” alone is unclear. “16,000 samples per second” tells us what it counts. A two-second mono recording therefore contains 32,000 samples. The seconds cancel when we multiply samples per second by seconds.

If each sample uses 16 bits, divide by eight to get two bytes per sample. Now multiply 32,000 samples by two bytes: the audio values use 64,000 bytes. The file header needs extra space. A compressed file needs a different calculation.

### Turn the calculation into a reusable rule

A letter can stand for a number we have not filled in yet. Let \(f_s\) mean sampling rate, \(T\) duration in seconds, \(C\) channel count and \(b\) bits per sample per channel. The subscript s is a label that reminds us the rate is for samples.

\[\text{bytes of audio data} = \frac{f_s \times T \times C \times b}{8}\]

Read this in words before using it: samples each second, multiplied by seconds, channels and bits per value, then divided by eight bits per byte. If you need duration instead, divide the available bytes by the number of bytes used each second.

### Understand powers as repeated multiplication

\(2^3\) means \(2\times2\times2=8\). A bit has two possible values. Two bits give four possible combinations; three give eight. That is why powers of two appear when we count the possible stored levels for a sample.

### Understand a logarithm as the reverse question

\(10^2=100\) asks what happens when ten is multiplied by itself twice. \(\log_{10}(100)=2\) asks which power of ten gives 100. These are two ways to describe the same relationship.

Decibels, written dB, use logarithms to express ratios. For comparable amplitudes, use \(20\log_{10}(A_2/A_1)\). For powers, use \(10\log_{10}(P_2/P_1)\). A ratio compares the new amount with a reference amount. Doubling amplitude gives about 6 dB; doubling power gives about 3 dB. Do not swap the two formulas.

An absolute claim such as “this is 60 dB” needs a reference. A change such as “the amplitude rose by 6 dB” describes a ratio under the stated measurement conditions.

### Use other logarithm bases

The base states which repeated multiplication you are reversing. Since \(2^6=64\), \(\log_2(64)=6\). The natural logarithm, written ln, uses the constant e, approximately 2.718, as its base. A calculator's log and ln buttons may therefore mean different functions. State the base you use.

The amplitude-to-power comparison above assumes comparable physical conditions, including the same relevant impedance: the property connecting signal amplitude with power in that setting. Under those assumptions, doubling amplitude multiplies power by four. Do not use that relationship across measurements with different references or conditions.
EXAMPLE:: For uncompressed PCM payload, let \(f_s\) be samples/second, \(T\) seconds, \(C\) channels and \(b\) bits/sample/channel. Headers and compression are excluded.

\[\begin{aligned}
B&=\frac{f_sTCb}{8}\\
 &=\frac{16{,}000\times2\times1\times16}{8}\\
 &=64{,}000\ \text{bytes}.
\end{aligned}\]

Under the stated comparable-amplitude/impedance assumptions:

\[\begin{aligned}
20\log_{10}(2)&\approx6.02\ \mathrm{dB}\quad\text{(amplitude ratio)},\\
10\log_{10}(2)&\approx3.01\ \mathrm{dB}\quad\text{(power ratio)}.
\end{aligned}\]
EXPLANATION:: The two decibel answers differ because amplitude and power are different quantities. The payload is 64,000 decimal bytes; this does not include the file header. A stereo recording at the same rate and depth doubles the payload because it stores two channels.
PITFALL:: A value in dB needs a ratio or reference. “The audio is 60 dB” is incomplete unless the measurement and reference are specified. Do not turn digital sample values into hearing-safety claims.
EXERCISE:: Calculate the payload for 0.5 seconds of stereo PCM at 48 kHz and 16 bits/sample. Show every conversion. Then find the duration of 24,000 mono samples at 16 kHz. Explain the difference between doubling amplitude and doubling power in the stated matching conditions.

QUESTION:: Which formula gives uncompressed PCM payload bytes?
CORRECT:: Sample rate × duration × channel count × bits per sample ÷ 8.
WRONG1:: Sample rate ÷ duration, regardless of channels.
WRONG2:: Duration × decibels, because louder audio always uses more bytes.
FEEDBACK:: PCM payload size follows the number and representation of stored samples, not the signal's loudness.

ID:: V07
BRIDGE:: You can read a list of numbers and multiply and add them. We will start with two numbers, then build up to a batch of recordings.
CONCEPT:: A speech program handles many numbers at once. Vectors, matrices and tensors are ways to organise those numbers so you know what each position means.
MECHANISM:: A vector is an ordered list; a matrix is a table; a tensor can have more axes. Name every axis and check that the sizes match before combining arrays.
TEACHING:: ### Start with a short list

Suppose we describe an invented sound using two measurements: its average level and its duration. Store them in a fixed order, such as [level, duration]. A vector is an ordered list like this. If you swap the entries, the numbers now describe the wrong things even though the list still has two items.

### Use one row of weights

A weight tells a calculation how much to use of an input. Take the vector [2, 3] and weights [1, 2]. Multiply matching positions and add: \(1\times2+2\times3=8\). This is a dot product.

Use a second row of weights, [−1, 1], on the same input. This time \(-1\times2+1\times3=1\). The two rows give two outputs. Put those rows together in a rectangular table and you have a matrix.

A bias is a number added after the weighted sum. Adding biases [0, 4] changes the two outputs from [8, 1] to [8, 5]. That is the calculation in the worked example.

### Check the shape before calculating

Shape describes the number of entries along each direction, or axis. A matrix with two rows and two columns has shape (2, 2). Each row needs two input numbers, so it can multiply a two-entry column vector. A row with four weights cannot pair up with an input containing five entries.

The convention matters: some code stores each input as a row, and some maths writes it as a column. Check the chosen convention rather than memorising one expression for every program.

### Give each axis a meaning

A tensor is an array that can have more than two axes. Suppose four recordings each have 100 time frames, with 80 measurements per frame. With axes [recording, time, feature], the shape is (4, 100, 80).

A feature is a measurement supplied to a model. A batch is a group processed together. Here the first axis counts recordings in the batch. The second counts time frames. The third counts features. Writing those names beside the shape helps prevent a program from treating features as moments in time.
EXAMPLE:: Use a column-vector convention. The input and bias have shape \((2,1)\); the weight matrix has shape \((2,2)\).

\[\mathbf{x}=\begin{bmatrix}2\\3\end{bmatrix},\quad
W=\begin{bmatrix}1&2\\-1&1\end{bmatrix},\quad
\mathbf{b}=\begin{bmatrix}0\\4\end{bmatrix}.\]

\[\begin{aligned}
\mathbf{y}&=W\mathbf{x}+\mathbf{b}\\
&=\begin{bmatrix}1\cdot2+2\cdot3+0\\-1\cdot2+1\cdot3+4\end{bmatrix}
=\begin{bmatrix}8\\5\end{bmatrix}.
\end{aligned}\]

A batch of four clips, each with 100 frames and 80 features per frame, has shape \((4,100,80)\) when the axes are batch, time, feature.
EXPLANATION:: Each matrix row consumes both input features. The bias does not change the output shape. The three-axis example has 32,000 numeric entries, but says nothing about their numeric precision, sampling rate or physical duration unless the frame construction is also defined.
PITFALL:: A shape-compatible operation can still combine the wrong quantities. Broadcasting can silently repeat values across an unintended axis. Name and check each axis before interpreting a result.
EXERCISE:: Recalculate the example for x = [1, 0]. Then write a matrix that turns [left, right] into [left + right, left - right]. Apply it to [3, 1]. Finally explain why a (3, 4) matrix cannot multiply a (5, 1) column vector.

### Build or inspect it

Implement dot(a,b) with a loop and reject unequal lengths. Check [1,2] with [3,4], and [1,1] with [1,-1]. Do the same arithmetic by hand, then explain what each coordinate represents in your own two-feature example.
SOLUTION:: The first result is [1, 3]. The sum/difference matrix is \(\begin{bmatrix}1&1\\1&-1\end{bmatrix}\), producing [4,2]. In the invalid multiplication, the inner dimensions 4 and 5 do not match. This is a structural error, not a rounding problem.

### Practical check

The dot products are 11 and 0. Check lengths before iterating so a missing coordinate cannot disappear silently. Initialise total to zero and add a[i] * b[i] for every index.
CHALLENGE:: A model receives \((8,50,40)\) with batch/time/feature axes. It applies a 12-output linear layer independently at each time step. State the weight shape, output shape, number of weights and number of biases. Explain what would change if time and feature were accidentally swapped.
CHALLENGE_SOLUTION:: Under the column-vector rule y=W x+b from the example, weights have shape \((12,40)\), output (8,50,12), with 480 weights and 12 biases. Swapping time and feature changes the last-axis length to 50 and makes the existing weights incompatible; rebuilding weights would define a different function over time positions, not repair the original meaning. A library using row vectors \(y=xW+b\) stores weights as \((40,12)\); the same 480 coefficients are transposed. State the convention before comparing shapes.
QUESTION:: What must agree in ordinary matrix multiplication?
CORRECT:: The left matrix's column count and the right matrix's row count.
WRONG1:: Only the total number of values in the two arrays.
WRONG2:: Every axis must have the same size.
FEEDBACK:: Inner dimensions align the entries used by each dot product. Matching dimensions still requires matching semantic axes.

ID:: V08
BRIDGE:: V06 introduced simple equations and V07 introduced arrays. We will begin with one adjustable number, so you can follow every update by hand.
CONCEPT:: Training adjusts numbers inside a model to reduce its mistakes. A gradient tells us how a small change to each adjustable number would change the error.
MECHANISM:: Define a loss, calculate its gradient at the current parameters, take a controlled step in the opposite direction, then check the new loss.
TEACHING:: ### Give a mistake a number

Suppose our adjustable value is \(w\), and we want it to be 3. Define an error score \(L(w)=(w-3)^2\). The letter L stands for loss: a number we want to make smaller.

At \(w=0\), the loss is 9. At \(w=2\), it is 1. At \(w=3\), it is 0. Squaring makes the score non-negative and gives larger misses a larger penalty.

### Ask which way reduces the loss

A derivative measures how quickly a function changes near one value. For this loss, the derivative is \(L'(w)=2(w-3)\). At zero it is −6. A negative slope means that increasing w slightly will lower the loss nearby.

You can check that meaning without trusting a symbol: at 0 the loss is 9, while at 0.1 the loss is 8.41. Moving a little to the right did reduce it.

### Choose a step size

The learning rate controls how large an update we take. With learning rate 0.1, subtract 0.1 times the derivative from the current value:

\[w_{\text{new}}=w_{\text{old}}-0.1L'(w_{\text{old}})\]

Starting at zero gives \(0-0.1(-6)=0.6\). Recalculate the loss: \((0.6-3)^2=5.76\). It is lower than 9. Repeat from 0.6 to obtain the next step in the example.

A step can be too large. The slope describes what happens nearby; it does not promise that a huge jump will help. Recalculate the loss after an update instead of assuming success.

### Extend the idea to several parameters

A parameter is an adjustable model number. With several parameters, compute how the loss changes with each one while holding the others fixed. That collection of derivatives is the gradient.

Calculate all parts of a gradient from the same current parameter values. Then update the parameters together. Changing one early and using it to calculate another old-step derivative mixes two different calculations.

A finite-difference check estimates a slope by comparing two nearby loss values. It is useful for checking small examples; the two-parameter exercise asks you to show the actual derivatives too.

### Differentiate a function inside a function

For \(L(w)=(2w-6)^2\), first call the inside expression u = 2w − 6. The outside square changes at rate 2u; the inside changes at rate 2. Multiply them: \(L'(w)=2(2w-6)\times2=4(2w-6)\). This is the chain rule. With several independent parameters, calculate one partial derivative at a time, treating the others as fixed.
EXAMPLE:: Start with a scalar squared loss, step size \(\eta=0.1\), and initial parameter \(w_0=0\).

\[L(w)=(w-3)^2,\qquad L'(w)=2(w-3).\]

\[\begin{aligned}
w_1&=w_0-\eta L'(w_0)=0-0.1(-6)=0.6,\\
L(w_1)&=(0.6-3)^2=5.76,\\
w_2&=0.6-0.1(-4.8)=1.08,\\
L(w_2)&=(1.08-3)^2=3.6864.
\end{aligned}\]

A central finite-difference check near \(w=1\) gives:

\[\frac{L(1.001)-L(0.999)}{0.002}\approx-4.\]
EXPLANATION:: The finite difference estimates slope by comparing nearby points. It is a check on this small calculation, not a substitute for a general proof or an instruction to launch a model experiment. All quantities are supplied, so pencil-and-paper reasoning is sufficient.
PITFALL:: A lower loss does not establish that a speech system understands a request. It only describes the chosen objective on the data used to compute it. Generalisation and useful behaviour require separate evidence.
EXERCISE:: Starting from w = 5 with rate 0.1, calculate two updates and their losses. Repeat the first update with rate 1.2. Explain what the comparison shows about step size. Then differentiate \(L(w)=(2w-6)^2\) using the chain rule.

### Build or inspect it

Write a loop that starts w at zero and performs five updates for \(L(w)=(w-3)^2\) with learning rate 0.1. Print step, w and loss after each update. Explain why using the new w to report the old loss would make the log confusing.
SOLUTION:: From five, the updates are 4.6 then 4.28, with losses 2.56 and 1.6384. At rate 1.2, the first new value is 0.2 and loss is 7.84, worse than the original loss four. The composed derivative is \(4(2w-6)\), equivalently \(8w-24\).

### Practical check

After five updates w is 2.01696 and loss is approximately 0.966368. At each iteration calculate the derivative at the current w, update w, then calculate and label the new loss. This is a toy numeric program, not a speech-model experiment.
CHALLENGE:: For \(L(a,b)=(a-1)^2+2(b+2)^2\), start at (3,−1) with rate 0.1. Compute the gradient, one update and the old/new loss. State why one successful update is not a universal convergence argument.
CHALLENGE_SOLUTION:: The gradient is \((2(a-1),4(b+2))=(4,4)\). Subtract 0.1 times each component to get \((2.6,-1.4)\). Old loss is \(4+2=6\); new loss is \(1.6^2+2(0.6^2)=3.28\). This quadratic and step behaved well once. Different curvature, non-convex losses and step sizes can behave differently; one observed decrease does not prove convergence.
QUESTION:: What does the gradient-descent update subtract?
CORRECT:: The learning rate multiplied by the gradient of the chosen loss.
WRONG1:: The loss itself from every parameter, regardless of its derivative.
WRONG2:: A fixed amount of audio from the input waveform.
FEEDBACK:: A loss value measures error; its gradient describes local parameter sensitivity. They play different roles.

The notation \(P(A\mid B)\) means the probability of A when we restrict attention to cases with B. Read the vertical line as “given”. In this table, \(P(\text{error}\mid\text{noisy})\) uses only noisy clips.

CONCEPT:: To find out whether a speech system works on new recordings, keep some recordings out of every training and tuning decision. Otherwise you may mistake familiarity for useful learning.

Training data is used to fit the model's adjustable numbers. Validation data helps you make choices while building the system, such as selecting settings. Test data is saved for a final check of a fixed approach.

Once you use a test result to choose the next setting, that test data is helping development. Repeating the process does not give you a fresh final check each time.

### Find information that crosses the split

Data leakage means information reaches a stage where it should have been unavailable. A copied recording in both training and test sets is a clear example. The model may already have encountered the very audio you call new.

Read A1 and A2 in the example. A2 is a duplicate of A1. Putting A1 in training and A2 in testing does not test new audio. If your claim is about new speakers, recordings from the same speaker should also stay on the same side of that boundary.

A new-speaker test holds out speakers. A future-session test may need to hold out later sessions. Recordings can also share a room, device or source file. Write down which kinds of new situations your claim covers, then group related recordings before splitting them.

If a preprocessing step learns an average or another setting from the data, learn that setting from training data only. Applying the learned setting to the held-out data is different from calculating it using the held-out answers.

BRIDGE:: You only need to count and divide. A second is a unit of time; a millisecond is one thousandth of a second. We will explain each sound term before using a formula.
CONCEPT:: Sound begins with vibration. A microphone responds to changing air pressure, and a recording stores measurements of that change. We will use a simple repeating tone to understand frequency, amplitude and phase.
MECHANISM:: Frequency counts cycles per second. Period measures the time for one cycle. Amplitude describes signal size. Phase compares position within a cycle. Sampling rate describes the recording process, not the sound's pitch.
TEACHING:: ### Picture a vibrating speaker

A speaker cone moves back and forth. That movement produces changes in air pressure. A microphone responds to those changes. If you draw the signal over time, the line moves above and below a centre level. That drawing is a waveform.

The horizontal direction shows time. The height shows the signal's value. In a recording, that value depends on the microphone and recording settings; it is not automatically a calibrated measurement of loudness in the room.

### Count complete repetitions

One complete repeat of a regular waveform is a cycle. Frequency tells you how many cycles happen in one second. Its unit is hertz, written Hz. A 200 Hz tone repeats 200 times per second.

The time for one cycle is its period. If 200 cycles fit in a second, one cycle takes one second divided by 200: 0.005 seconds, or 5 milliseconds.

\[\text{period} = \frac{1}{\text{frequency}}\]

This relationship describes a repeating tone. Speech usually mixes several changing patterns, so a whole spoken sentence does not have one fixed period.

### Compare height and timing

Amplitude describes the size of the signal. For the same simple tone and recording setup, a larger amplitude generally sounds louder. Pitch is related to how quickly a repeating pattern cycles. Doubling the height does not double its frequency.

Phase describes where a repeating wave is within its cycle compared with a chosen starting point. Two matching waves can add together. If one is exactly opposite and aligned with the other, their values can cancel in an ideal example. Real-room noise is much less predictable.

### Separate a sound from the rate used to record it

A 200 Hz tone describes the sound's repetition. A recording rate of 16,000 samples per second describes how often we measure it. Those are two different counts. The next lesson turns that distinction into a recording you can inspect.

A pure tone has one frequency component. A more complex repeating sound can contain its fundamental repetition frequency and harmonics at whole-number multiples. For a 150 Hz fundamental, those positions are 150, 300, 450 Hz and so on. The strongest component need not be the fundamental. Perceived loudness also depends on frequency, playback and the listener; an uncalibrated waveform height is not an absolute room sound-pressure measurement.
EXAMPLE:: Take a repeating 200 Hz tone. That means 200 complete cycles per second.

\[\text{time for one cycle}=\frac{1\ \mathrm{s}}{200}=0.005\ \mathrm{s}=5\ \mathrm{ms}.\]

Twenty milliseconds is 0.020 seconds, so:

\[\text{cycles in 20 ms}=200\times0.020=4.\]

For an ideal cancellation example, take signal values [1, 0, −1, 0]. Add the exactly opposite, aligned values [−1, 0, 1, 0]. Each pair sums to zero. This special arithmetic does not describe arbitrary real-room noise.
EXPLANATION:: Cancellation in this ideal arithmetic example requires exact alignment and equal opposite signals. Real rooms contain reflections, different paths and changing delays. The example explains phase sensitivity; it does not establish that any noise can be removed by simply reversing recorded samples.
PITFALL:: Frequency is not sample rate. A 200 Hz tone can be represented by many samples per cycle; a 16 kHz sampling rate says how often measurements are stored, not that the sound's pitch is 16 kHz.
EXERCISE:: Calculate periods for 100 Hz, 250 Hz and 1 kHz. Count how many cycles each completes in 40 ms. Draw two cycles of a 250 Hz signal, labelling the time axis in milliseconds. Explain what changes if amplitude halves while frequency stays fixed.

ID:: V12
BRIDGE:: V11 explained a waveform as a picture of a changing sound signal. Here we turn that changing signal into stored numbers. Start with one microphone channel; we will add stereo after the basic idea is clear.
CONCEPT:: A digital recording is a long list of numbers. Each number is one measurement of the sound signal. The sampling rate tells you how many measurements are stored for each second of audio.
MECHANISM:: A sample is one signal measurement. Sampling rate is measurements per second per channel. Use frame count ÷ sampling rate for duration. Resampling computes new values; changing the rate label alone changes how quickly the existing values play.
TEACHING:: ### What is one sample?

Imagine measuring the microphone's signal at one instant and writing the value down. That one measurement is a sample. Keep measuring at evenly spaced times and you get a list of samples. The computer stores that list, rather than storing a tiny piece of spoken text for each moment.

The list might begin 0.0, 0.1, 0.3, 0.1. These are signal values. They are not words, seconds or sound frequencies. A waveform graph puts the sample values on the vertical axis and their times on the horizontal axis.

### What does 16,000 Hz mean?

A sampling rate of 16,000 Hz means that one channel stores 16,000 samples for every second of sound. Hz means “per second” here. The same rate can be written 16 kHz because k means one thousand.

For a two-second mono recording, count 16,000 samples in the first second and another 16,000 in the second. The total is 32,000 samples. Mono means one channel.

\[\text{sample count} = \text{seconds} \times \text{samples per second}\]

You can work backwards too. If a mono recording has 48,000 samples at 16,000 samples per second, it lasts three seconds: divide 48,000 by 16,000. The rate is not the number of words, and it does not mean the speaker's voice has a pitch of 16 kHz.

### Why does changing the rate matter?

Suppose 48,000 samples describe one second of sound recorded at 48 kHz. If you keep all the samples but tell a player to play only 16,000 each second, it needs three seconds to finish. The recording becomes slower and lower in pitch. You changed the playback instructions, not the recorded information.

Resampling means calculating a new list of samples for a different rate while keeping the intended duration. Correctly changing that one-second recording from 48 kHz to 16 kHz gives about 16,000 output samples for one second. Boundary handling can affect the exact count for other clip lengths.

A lower rate cannot represent every rapid change that a higher rate can. A low-pass filter removes frequencies too high for the new rate before they turn into misleading lower frequencies. That misleading result is called aliasing. The ideal sampling rule requires a rate greater than twice the highest frequency you want to retain; real filters also need room to work. More samples cannot restore detail that was already lost.

### Add the second channel

Stereo stores two channels, usually left and right. One audio frame holds the samples for both channels at the same time position. A one-second stereo file at 16 kHz has 16,000 audio frames and 32,000 individual sample values. It still lasts one second. Calculate its duration with frames divided by sampling rate.

### Store each value in bytes

Bit depth tells you how many bits describe each stored value. In our uncompressed 16-bit examples, one value takes two bytes because eight bits make a byte. Rounding a measurement to an available stored level is called quantisation.

For one second of 16 kHz mono, the audio values take 16,000 × 2 = 32,000 bytes. Stereo takes twice that. A file header adds extra bytes describing the recording.

Our lab uses signed 16-bit little-endian PCM. PCM stores the measured values directly. Signed means values may be negative. Little-endian means the lower-value byte of a multi-byte number is stored first. For this format, the two hexadecimal bytes 01 00 represent 1; FF FF represents −1. You can inspect this later without memorising it to understand sampling rate.

### Distinguish the recording from the file format

A codec describes how audio is encoded and decoded. Some codecs compress it to use less space. A container packages the encoded audio with information about it. WAV is a container, and not every WAV file uses the PCM format in our lab.

When an audio tool expects 16 kHz mono, check both the rate and the channel count. Decoding a file, mixing stereo to mono and resampling are separate operations. Renaming the file does none of them.
EXAMPLE:: A mono recording has 32,000 samples. Its sampling rate is 16,000 samples per second.

How long is it? Divide the number of samples by the number used in one second:

\[\text{duration}=\frac{32{,}000\ \text{samples}}{16{,}000\ \text{samples/second}}=2\ \text{seconds}.\]

Each 16-bit sample needs two bytes, so the stored audio values occupy:

\[32{,}000\times2=64{,}000\ \text{bytes}.\]

For stereo of the same duration and rate, there are still 32,000 time positions, or audio frames. Each frame now contains two channel values:

\[32{,}000\ \text{frames}\times2\ \text{channels}\times2\ \text{bytes}=128{,}000\ \text{bytes}.\]

These counts exclude the file header and assume the uncompressed PCM format described above.
EXPLANATION:: First use the rate to turn the count into time: two groups of 16,000 samples mean two seconds. Next use the bit depth to turn each stored value into bytes: 16 bits is two bytes. Finally add the channel count. Stereo stores two values for each time position, so it doubles the audio-data size without doubling duration. Count the file header separately.
PITFALL:: A higher sampling rate is not a promise of better sound. The microphone, original recording, retained frequencies and later processing all matter. Use the rate the chosen model expects, and resample the actual values when a conversion is needed.

CONCEPT:: Speech sounds come from coordinated movements of the mouth, tongue, lips and voice. Written letters do not describe those sounds reliably, so speech technology often needs a separate pronunciation representation.
MECHANISM:: Describe where a sound is made, how air moves and how voicing is involved. Use sound symbols when spelling is unclear, and state the language or pronunciation convention.
TEACHING:: ### Compare what your mouth does

Say “pa”, “ba” and “ma” gently in your usual voice, if comfortable. Your lips come together for all three first sounds. That shared location is called the place of articulation. Bilabial means “using both lips”.

The sounds differ in how air moves. For /p/ and /b/, the lips briefly stop the air before releasing it. They are stop consonants. For /m/, air can pass through the nose; it is a nasal sound. This kind of difference is called manner of articulation.

### Add voicing

Voicing concerns vibration of the vocal folds. In a conventional introductory description, /b/ and /m/ are voiced and /p/ is voiceless. Real timing varies across languages, accents and positions within words, so these labels are a starting description rather than an exact account of every recording.

### Separate sounds from spelling

The word “ship” has four letters. A common English sound transcription uses three symbols: /ʃ/, /ɪ/ and /p/. The two letters “sh” represent one consonant sound in that word.

The International Phonetic Alphabet, or IPA, provides symbols for describing speech sounds. A phoneme is a sound category that can distinguish words in a language. Broad transcription records selected categories; a more detailed transcription can record finer pronunciation differences.

### Connect pronunciation to a voice product

A text-to-speech system needs to decide how a name or word should sound. Reading each letter separately will not solve English pronunciation. A speech recogniser also needs to cope with different realisations of words.

State which language and pronunciation convention an example uses. Ask how a user can correct a name. An unfamiliar accent or pronunciation is not automatically a mistake to remove. Your product should make room for the people who will use it.

### Name two more sound patterns

A fricative uses a narrow airflow opening that creates friction, as in a common English /s/. An affricate begins with a stop-like closure and releases into friction, as in a common /tʃ/ at the start of “chip”. Compare the action, not just the spelling. Adjacent sounds also affect each other's movements; this overlap is called coarticulation.

A tap uses one very brief contact at an articulatory location. A trill uses repeated contacts driven by the airflow. These are additional manners of articulation; learn them by comparing the described movement, not by assuming a spelling has the same sound in every language.

ID:: V14
BRIDGE:: V11 introduced frequency and V13 introduced speech production. A useful model treats the vocal tract as a changing acoustic tube: its shape changes which parts of the sound it emphasises. Resonance means the system responds more strongly near certain frequencies. We will use that idea to separate pitch from vowel shaping.
CONCEPT:: Your voice has a vibrating source and a changing sound-shaping passage. Separating those two jobs helps explain why pitch can change while a vowel still sounds like the same vowel.
MECHANISM:: The source supplies a repeating signal. The filter strengthens some source harmonics and weakens others. Harmonics follow the source repetition; formants describe resonances of the vocal tract.
TEACHING:: ### Separate making the buzz from shaping it

During a voiced sound, the vocal folds create a repeating source. The vocal tract—the spaces through the throat and mouth—changes which frequencies are emphasised. A simple source–filter model treats those as two separate jobs.

The source's basic repetition rate is its fundamental frequency, written \(F_0\). At 100 Hz, the pattern repeats 100 times each second. A repeating source can also contain harmonics: components at 200, 300, 400 Hz and so on.

### Understand a formant

The vocal tract emphasises certain frequency regions because of its shape. These resonant regions are called formants. Changing tongue and mouth position changes that shape and helps distinguish vowels.

A harmonic is a component related to the source's repetition. A formant describes a resonance of the sound-shaping passage. They are not two names for the same thing.

### Change one part of the example

Start with a source at 100 Hz and filter resonances near 500 and 1,500 Hz. Raise only the source to 200 Hz in this simplified model. The harmonics now occur at 200, 400, 600 Hz and so on. The filter resonances stay near 500 and 1,500 Hz because we did not change the filter.

You may no longer have a harmonic exactly at a resonance. That is why the tallest visible harmonic is not always a direct measurement of a formant. The resonance shapes the strengths of the harmonics that are present.

### Compare that with faster playback

Playing an unchanged recording twice as fast moves all its recorded frequencies upward and halves its duration. That changes more than the source pitch. A claim that a tool changes “only pitch” therefore needs a comparison that also checks duration and the sound's spectral shape.

Real speech production can couple the source and vocal tract. Keep the model's assumptions in mind when using it to explain a real voice.
EXAMPLE:: Keep the simplified source and filter separate:

\[F_0=100\ \mathrm{Hz},\qquad f_k=kF_0\quad(k=1,2,3,\ldots).\]

The initial harmonic grid is \(100,200,300,\ldots\ \mathrm{Hz}\). Assume filter resonances near \(500\) and \(1{,}500\ \mathrm{Hz}\).

If the source changes to \(F_0=200\ \mathrm{Hz}\) while that simplified filter stays fixed, the grid becomes \(200,400,600,\ldots\ \mathrm{Hz}\). The filter's resonant regions remain near the same two values; harmonics and formants are different objects.
EXPLANATION:: Doubling F0 changes the harmonic grid; it does not, in this simplified model, double the formant frequencies. The source may sample a filter envelope sparsely, so one cannot read a resonance by blindly selecting the tallest harmonic.
PITFALL:: Pitch shifting and changing vowel quality are not the same transformation. A model that separates them approximately still has limitations, especially for rapid, mixed or irregular phonation.
EXERCISE:: Draw a harmonic grid for F0 values 100 and 250 Hz up to 2 kHz. Overlay a broad resonant region at 700 Hz. Explain why the strongest nearby harmonic may appear at different locations. Then list two reasons real speech would depart from this stationary diagram.
SOLUTION:: At 100 Hz the nearby harmonics include 600,700,800; at 250 Hz they include 500,750,1000. A broad envelope weights whichever harmonics exist. Articulator movement changes the filter over time, and excitation may be irregular or mixed with turbulence. The diagram cannot fix either behaviour.
CHALLENGE:: A colleague doubles all frequencies in a recording and claims only pitch changed. Explain the expected effect on resonances and duration under simple sample-rate relabelling, and describe what evidence a pitch-only claim would need.
CHALLENGE_SOLUTION:: Simple faster playback raises both harmonic and resonant frequencies and shortens duration. A pitch-only transformation needs a different method and a stated preservation target. Compare duration and spectral-envelope behaviour on appropriate permitted material; a pleasant listening impression alone does not establish preservation.
QUESTION:: In the simplified source–filter model, what primarily sets harmonic spacing?
CORRECT:: The repetition rate of the voiced excitation source.
WRONG1:: The filename of the recording.
WRONG2:: The first formant always equals the fundamental frequency.
FEEDBACK:: Source repetition and filter resonances are distinct model components. Their observed interaction still depends on analysis and real-speech limitations.

ID:: V15
BRIDGE:: You know samples and sampling rate from V12, and frequency from V11. V07 explained arrays. We will build the pictures first, then name the calculations behind them.
CONCEPT:: A waveform shows how an audio signal changes over time. A spectrum shows its frequency components. A spectrogram shows how those components change through a recording.
MECHANISM:: A spectrum describes frequencies in one selected piece of sound. Repeating that calculation over short windows produces a spectrogram. Window length, hop and display settings all affect what you see.
TEACHING:: ### Ask what is inside one short sound

A sound may combine several tones. A Fourier transform calculates how much of each frequency pattern is present in a selected piece of signal. For stored samples, the calculation is a discrete Fourier transform, or DFT. FFT names a fast way of calculating it.

The result describes magnitude and phase. Magnitude tells you the size of a frequency component. Phase describes its position within a cycle relative to the chosen reference. Keeping only magnitude loses phase information.

### Select a short window

Speech changes while we speak, so one spectrum for an entire sentence hides changes. Select a short stretch of samples, calculate its spectrum, move forward a little, and repeat. This is the short-time Fourier transform, or STFT.

The stretch is called a frame or window. Hop length is how far you move before the next frame. Overlapping frames share samples.

At 16,000 samples per second, a 400-sample frame covers \(400/16000=0.025\) seconds: 25 ms. Moving 160 samples between frames gives a 10 ms hop. A 10 ms hop does not make the window 10 ms long.

### Read a spectrogram

A spectrogram puts time along one axis and frequency along the other. Colour or brightness represents the component size, often on a logarithmic scale. Each time slice comes from one short-window spectrum.

The window length affects the frequency detail you can distinguish and how much time is mixed into one slice. A longer window can separate nearby stable frequencies better, but combines a longer period of changing speech.

### Understand what the frequency grid means

For a DFT using N samples at sampling rate \(f_s\), neighbouring frequency bins are \(f_s/N\) Hz apart. A bin is one position in the transform's frequency grid. With 400 samples at 16 kHz, the spacing is 40 Hz. With 800 observed samples it is 20 Hz.

Adding zeros to 400 samples before an 800-point transform draws a denser grid, but it does not record an extra 400 samples of sound. This is called zero-padding. The shape used to taper the edges of a frame is a window function; it affects how energy spreads between bins.

When comparing plots, keep the sampling rate, window, hop, transform size and colour scale visible. Changing a colour scale can make the same sound look very different.

### Work a four-sample transform without guessing

The later exercise asks for four DFT coefficients. We can learn the arithmetic with a different input: \(x=[1,0,-1,0]\). Name the input positions n = 0, 1, 2, 3 and the output bins k = 0, 1, 2, 3. Use the unnormalised forward DFT convention below.

A complex number stores two components, written \(a+bi\), where \(i^2=-1\). Its magnitude is \(\sqrt{a^2+b^2}\). The imaginary component is a mathematical coordinate, not a second microphone channel.

For this four-point case, use these multiplying factors in input order:

- Bin 0: [1, 1, 1, 1]. Multiply and add to get 1 + 0 − 1 + 0 = 0.
- Bin 1: [1, −i, −1, i]. The sum is 1 + 0 + 1 + 0 = 2.
- Bin 2: [1, −1, 1, −1]. The sum is 1 + 0 − 1 + 0 = 0.
- Bin 3: [1, i, −1, −i]. The sum is 1 + 0 + 1 + 0 = 2.

The result is [0, 2, 0, 2]. Each bin used the same rule—multiply matching positions, then add—with a different repeating factor pattern. For N samples, the compact formula is:

\[X[k]=\sum_{n=0}^{N-1}x[n]\left[\cos\left(\frac{2\pi kn}{N}\right)-i\sin\left(\frac{2\pi kn}{N}\right)\right].\]

The summation sign means add the terms for every input position n. The cosine and sine generate the factor patterns just used. For N = 4 they use angles 0, a quarter-turn, a half-turn and three quarter-turns; cosine values are 1, 0, −1, 0 and sine values are 0, 1, 0, −1 around those positions.

Now change the input to [0, 1, 0, −1]. The same factors give [0, −2i, 0, 2i]. Its magnitudes are still [0, 2, 0, 2], but the components have different phase. This shows concretely why magnitude alone loses information. The independent task changes the input again; reuse the factors, not the previous answers.
EXAMPLE:: Let \(f_s=16{,}000\ \mathrm{Hz}\), frame length \(N=400\), and hop length \(H=160\).

\[\begin{aligned}
T_{\text{window}}&=\frac{N}{f_s}=25\ \mathrm{ms},\\
\Delta f&=\frac{f_s}{N}=40\ \mathrm{Hz},\\
T_{\text{hop}}&=\frac{H}{f_s}=10\ \mathrm{ms}.
\end{aligned}\]

For \(N=800\) at the same sample rate:

\[T_{\text{window}}=50\ \mathrm{ms},\qquad\Delta f=20\ \mathrm{Hz}.\]

Zero-padding 400 observed samples to length 800 does not observe 50 ms of sound. It changes the display grid, not the duration of the evidence.
EXPLANATION:: The 800-sample observed window can resolve finer frequency structure under appropriate conditions because it contains more time information. Padding a shorter window changes the display grid rather than the amount of observed evidence. A 10 ms hop does not make a 25 ms window instantaneous.
PITFALL:: A spectrogram is an analysis choice, not a photograph of uniquely determined frequency truth. Different windows and scales can make the same recording look different.

BRIDGE:: V15 introduced spectra, windows and spectrograms. Start by calculating four small averages; you do not need a model or an audio package to follow this example.
CONCEPT:: Audio preprocessing changes or summarises a signal before a model uses it. We will start with a two-sample averaging filter, then follow the steps that produce common speech features.
MECHANISM:: First understand the signal operation and its boundary rules. Then follow the feature-making steps in order. Equal array sizes do not guarantee that two feature sets mean the same thing.
TEACHING:: ### Calculate a tiny filter by hand

A filter combines input samples according to a rule. Take the current sample and the previous one, multiply each by one half, and add them. For input [2, 4, 0, 2], assume the previous sample before the recording began was zero.

The first output is half of 2 plus half of 0: 1. The second is half of 4 plus half of 2: 3. The next two are 2 and 1. Every output follows the same local rule.

Convolution is a general way of sliding a set of weights across a signal and summing products. Here the weights are [1/2, 1/2]. A causal filter uses the current and earlier samples, so it does not need to wait for future samples.

### Decide what happens at the ends

We assumed zero before the first sample. We also stopped after four outputs. If we let the filter finish after the input ends, there is one more output: half of the final 2 plus half of a new zero, which is 1.

These choices affect output length and timing. Record them when you compare filters; a one-sample difference may come from an end rule rather than a wrong multiplication.

### Turn a spectrum into features

A feature is a measurement provided to a model. A common speech preparation sequence is:

1. Split the waveform into short overlapping frames.
2. Apply a window function and calculate a spectrum for each frame.
3. Combine frequency information into mel bands: groups arranged on a scale that roughly reflects differences in human pitch perception.
4. Apply a logarithm so a wide range of values is easier to handle. Define a small positive floor so you never take the log of zero.
5. If the model expects MFCCs, apply a further transform to the log-mel values. MFCC means mel-frequency cepstral coefficients; it names those transformed features.

### Match what the model expects

Two feature arrays can both contain 80 values per frame and still mean different things. They may use different rates, band limits, window alignment or normalisation. Normalisation rescales values using a stated rule.

Write down those choices along with whether you used magnitude or power. Use the local lab to connect the original waveform to the filtered result before trying to memorise the feature names.

### Work one complete two-band feature example

Suppose a selected frame has three power values [1, 4, 1]. Our invented two-band filter bank has rows [0.5, 0.5, 0] and [0, 0.5, 0.5]. The first weighted sum is \(0.5(1)+0.5(4)+0(1)=2.5\). The second is also 2.5.

Take the natural log of each energy. Both become approximately 0.9163. This bank only illustrates the calculation; real mel bands have documented frequency locations and usually many more bands.

For an unnormalised two-point DCT-II, the first output adds the two log values: about 1.8326. The second multiplies the first by \(\cos(\pi/4)=1/\sqrt2\) and the second by \(\cos(3\pi/4)=-1/\sqrt2\), then adds. Equal inputs therefore give zero.

Those are two MFCC-style coefficients for this stated tiny convention. Other normalisations rescale the outputs, so include the normalisation when exporting or comparing features.

\[\begin{aligned}
y[0]&=\tfrac12(2)+\tfrac12(0)=1,\\
y[1]&=\tfrac12(4)+\tfrac12(2)=3,\\
y[2]&=\tfrac12(0)+\tfrac12(4)=2,\\
y[3]&=\tfrac12(2)+\tfrac12(0)=1.
\end{aligned}\]

This convention truncates the filter tail. Full convolution would include the final sample \(y[4]=1\).

BRIDGE:: You know loss and gradients from V08 and data splits from V10. Here every input and expected answer is supplied, so you can compare predictions on paper.
CONCEPT:: Machine learning uses examples to choose a prediction rule. We will compare two small rules, measure their mistakes, and see why matching the training examples is only the beginning.
MECHANISM:: Choose inputs and labels, compare predictions with a simple baseline, then check new data using a score that matches the task.
TEACHING:: ### Decide what kind of answer you need

Predicting a number is regression. Predicting a category is classification. Estimating a duration is a regression task; deciding whether a clip contains speech is a classification task.

An input feature is a measurement available when making the prediction. A label is the answer provided for an example during supervised learning. The label should describe the task you actually want to solve.

### Compare a rule with a simple starting point

The example supplies pairs (0, 1), (1, 3) and (2, 5). The first number is the input; the second is the expected output. The rule \(\widehat y=2x+1\) predicts all three outputs exactly. The hat over y means “predicted y”.

For comparison, always predicting 3 is a baseline: a simple approach against which to judge a more complicated one. Its errors on the three pairs are 2, 0 and −2. Squaring gives 4, 0 and 4. Their mean is \(8/3\). This score is mean squared error, or MSE.

### Check data the rule did not learn from

Now use the separate pair (3, 8). Our first rule predicts 7, so its squared error is 1. A zero training error did not guarantee a correct new answer.

Overfitting means learning details that work well for the training examples but fail to carry over. Underfitting means the rule is too limited to capture useful patterns even in the training data. More complexity is therefore not automatically better.

### Match the score to the task

A number-prediction score and a category-prediction score answer different questions. For speech detection, count missed speech and false alarms separately if they have different consequences. For a duration estimate, look at the sizes and directions of errors.

Keep the training, development and final-check data separate. A few invented pairs teach the calculations, but they do not tell you how a model will perform on real speech.
EXAMPLE:: Fictional training pairs are \((0,1),(1,3),(2,5)\). For a prediction rule \(\widehat y\), define:

\[\mathrm{MSE}=\frac1n\sum_{i=1}^{n}(\widehat y_i-y_i)^2.\]

\[\begin{aligned}
\text{Model A: }\widehat y&=2x+1, & \mathrm{MSE}_A&=0,\\
\text{Baseline: }\widehat y&=\overline y_{\text{train}}=3,
& \mathrm{MSE}_{\text{base}}&=\frac{4+0+4}{3}=\frac83.
\end{aligned}\]

ID:: V18
BRIDGE:: V07 introduced weights and V08 introduced derivatives. We will use one input and one hidden value so none of the intermediate steps are hidden.
CONCEPT:: A neural network builds a prediction through several small calculations. Backpropagation works backwards through those calculations to find how each adjustable number contributed to the loss.
MECHANISM:: Calculate the prediction forwards, calculate loss changes backwards, then update the parameters together. Backpropagation is an efficient use of the chain rule, not a separate kind of error score.
TEACHING:: ### Follow the forward calculation

Start with input x = 2. Multiply it by weight w = 1 and add bias b = 0. That gives z = 2. Apply an activation function called ReLU: it returns the input if it is positive and zero otherwise. Here the hidden value h is still 2.

A hidden value is an intermediate result, not the final prediction. Multiply h by another weight, v = 3, to predict 6. The desired answer is 4, so squared loss is \((6-4)^2=4\). This sequence is a forward pass.

### Work backwards one link at a time

Near the prediction 6, the squared loss changes at rate \(2(6-4)=4\). To see how v affects the loss, multiply that rate by h, because changing v changes the prediction by h. The result is \(4\times2=8\).

For w, there are more links: w changes z by x; ReLU passes through a positive z unchanged; h changes the prediction by v; and the prediction changes the loss at rate 4. Multiply those local rates: \(4\times3\times1\times2=24\).

This is the chain rule: combine the rates along the calculation path. Backpropagation organises that calculation so the same intermediate derivatives can be reused efficiently.

### Update after computing every gradient

Use the original w, b and v to calculate all derivatives. Then subtract the learning rate times each derivative from the corresponding parameter. Recalculate the prediction and loss using the new values.

ReLU behaves differently when z is negative, and has a corner at zero. A derivative from the positive part should not be reused blindly in another part of the function. Real networks contain many more units, but the forward-and-backward bookkeeping follows the same idea.
EXAMPLE:: Given \(x=2,w=1,b=0,v=3,y=4\), use \(h=\operatorname{ReLU}(z)\):

\[\begin{aligned}
z&=wx+b=2,&h&=2,\\
\widehat y&=vh=6,&L&=(\widehat y-y)^2=4.
\end{aligned}\]

All gradients refer to those original parameter values:

\[\begin{aligned}
\frac{\partial L}{\partial\widehat y}&=2(6-4)=4,\\
\frac{\partial L}{\partial v}&=4h=8,\\
\frac{\partial L}{\partial w}&=4v\cdot1\cdot x=24,\\
\frac{\partial L}{\partial b}&=4v\cdot1=12.
\end{aligned}\]
EXPLANATION:: When updating several parameters, compute their gradients from one consistent forward pass before applying the step. Updating v early and then using its new value to calculate w's old-pass gradient would mix two different computations.
PITFALL:: A gradient is not an explanation that a model's decision is clinically, socially or linguistically correct. It measures local mathematical sensitivity of a specific objective.
EXERCISE:: Repeat the forward pass with w=-1, keeping the other supplied values fixed. Calculate prediction, loss and the gradients for w, b and v away from ReLU's zero point. Explain why this single example can leave the hidden unit inactive.

SOLUTION:: z=-2, h=0, prediction=0 and loss=16. The ReLU derivative is zero, so gradients for w and b are zero; dL/dv also equals zero because h=0. This path supplies no weight update from that example. Other inputs or architecture choices may behave differently.

### Practical check

The numeric derivative is approximately 24, agreeing with the analytic w gradient. Hold b and v fixed for this partial derivative. This tiny function check is not evidence about the quality of a trained speech model.

CORRECT:: They must refer to the same parameter state and forward computation.
WRONG1:: It guarantees the network cannot overfit.
WRONG2:: It makes the training labels correct automatically.

BRIDGE:: V07 introduced vectors and V18 introduced networks. Begin with two ordinary numbers. The full model uses vectors, but the small example shows what a weighted combination does.
CONCEPT:: Speech is a sequence: what happens at one moment can depend on other moments. Attention lets a model combine information from selected positions instead of treating every position in isolation.
MECHANISM:: Attention combines values using computed weights. Position tells the model about order, and a causal mask prevents it from using unavailable future information.
TEACHING:: ### Why order matters

The words “dog bites person” and “person bites dog” contain the same words in different orders. Their meanings differ. A sequence model needs a way to use both content and position. For speech, the order of audio frames matters too.

### Read attention as a weighted combination

Suppose the available values are 2 and 6. Give each a weight of 0.5. The result is \(0.5\times2+0.5\times6=4\). Attention computes weights that decide how much each available value contributes.

In a typical attention calculation, a query describes what a position is looking for, keys describe the available positions, and values contain information to combine. Comparing queries with keys produces scores. Softmax converts those scores into non-negative weights that sum to one.

### Decide which positions are available

A streaming model cannot use sound that has not arrived. A causal mask blocks future positions before the weights are calculated. If only the first value is allowed in our example, its weight becomes 1 and the other becomes 0. The output is then 2.

A mask changes what information the model can use. Hiding future values only in the display would not prevent a calculation from using them.

### Build a transformer from these parts

A transformer combines attention with other network layers. Positional information helps it distinguish order. Multiple attention heads can form different combinations of information. These mechanisms need training; their names do not guarantee that a model understands a sentence.

A large attention weight also does not prove why the final answer occurred. Later layers can change the result. Use attention as a calculation you can inspect, while checking explanations of overall model behaviour separately.

A token is one discrete unit of a sequence. In text it might be a word part; in an audio model its meaning depends on the representation. Check which unit and position each input actually represents.

### Calculate softmax and its mask

For scores \(s_i\), softmax uses \(\alpha_i=e^{s_i}/\sum_j e^{s_j}\). Exponentiation makes positive values, and division by their sum makes the weights total one. For scores [0, ln 3], exponentiation gives [1, 3], so the weights are [1/4, 3/4]. Applied to values [2, 6], they give \(2/4+18/4=5\).

Subtracting the largest score from every score before exponentiating gives the same weights while avoiding some numerical overflow. To mask a position, exclude it from the normalising sum or use an equivalent correctly implemented mask before softmax. Multiplying a forbidden value by zero only after it has influenced normalisation is not the same operation.

Scaled dot-product attention computes a score \(q\cdot k_i/\sqrt{d_k}\). The query q and key k are vectors, and \(d_k\) is their key dimension. Padding fills unused sequence positions so clips fit a shared array shape; a padding mask excludes those fake positions. A causal mask excludes forbidden future positions. Name both policies for unequal clip lengths.
EXAMPLE:: Equal allowed scores give equal softmax weights. With two scalar values \(v_1=2,v_2=6\):

\[\alpha=[0.5,0.5],\qquad
z=\sum_i\alpha_i v_i=0.5(2)+0.5(6)=4.\]

If the second position is unavailable future information, mask it before softmax:

\[\alpha_{\text{masked}}=[1,0],\qquad z_{\text{masked}}=2.\]

The mask changes which evidence can affect the output; it is not merely formatting.
EXPLANATION:: The toy example avoids matrix complexity while showing the effect of a causal boundary. Real attention uses vector values and many positions and heads. A high attention weight is not, by itself, a complete causal explanation of a model's answer.
PITFALL:: A system described as streaming may still use substantial lookahead or wait for a full chunk. Ask how much future context each prediction needs and include that delay in latency accounting.
EXERCISE:: With equal scores and scalar values [1,4,7], calculate unmasked attention. Then calculate attention at the middle position under a causal mask. Explain the result if a fourth padded position is mistakenly included with value 100 and equal score.

### Build or inspect it

Implement stable softmax for the two scores [0, ln(2)]: subtract the largest score before exponentiating, then divide by the sum. Apply it to values [3,9]. Test the single-allowed-key mask separately.
SOLUTION:: Unmasked output is four. At the middle position only [1,4] is available, so output is 2.5. Incorrectly including the padded value gives (1+4+7+100)/4=28 when all four are allowed. Padding is not harmless if the mask permits it to influence the computation.

### Practical check

The weights are [1/3,2/3] and the weighted value is 7. With only the first key allowed, its weight is 1 and the result is 3. Exclude masked entries before normalisation; do not treat a completely masked row as a valid distribution.

CORRECT:: A position cannot use later positions that the stated policy makes unavailable.
WRONG1:: Every token must attend equally to every other token.
WRONG2:: Attention weights prove a model's answer is correct.
FEEDBACK:: A mask restricts information flow. Correct masking does not establish language understanding or factual accuracy.

ID:: V21
BRIDGE:: V09 introduced probability and V19 introduced sequences. Here there are only two supplied candidate paths, so you can multiply their factors by hand.
CONCEPT:: A speech recogniser must connect a changing sound signal with a sequence of language units. Classical recognisers use possible sound states and probabilities to compare candidate paths through the recording.
MECHANISM:: Infer possible sound states, score how they fit the audio and state transitions, then search for a strong sequence. A path score is not automatically a calibrated confidence in a whole transcript.
TEACHING:: ### Separate what you hear from the state you infer

A recogniser observes measurements from successive audio frames. It does not directly observe a label saying “this frame is the middle of a vowel”. It must infer the underlying speech state from the measurements.

A hidden Markov model, or HMM, represents those unobserved states and the possible transitions between them. Hidden means the state is inferred. The Markov assumption says that, in this model, the next state depends on the current state rather than the entire earlier state history.

### Give a candidate path a score

A path is a proposed state sequence. Its score combines a starting probability, how well each state fits an observation, and the probabilities of moving between states.

For path A in the example, multiply 0.5, 0.8, 0.6 and 0.7 to obtain 0.168. Path B gives 0.144. A has the larger joint-path score among these two supplied possibilities.

### Search without listing everything

Real recordings permit too many paths to write down. Viterbi decoding keeps the best partial path reaching each state, then extends those partial paths. It uses shared subproblems to avoid repeating the same work.

A language model can add information about likely word sequences. That helps choose among acoustically plausible candidates, but common wording must not be mistaken for proof that those words were spoken.

### Know what your result means

The path factors and modelling assumptions are part of the calculation. A larger score for A here does not mean a 16.8% probability that the final transcript is correct. It compares the stated paths under the supplied model. Keep that distinction when interpreting recogniser scores.

### Fill a two-state table one cell at a time

A trellis is a table with time steps across one direction and possible states along the other. Use these fixed values:

- Start probabilities: A = 0.6, B = 0.4.
- Transition probabilities: A→A = 0.7, A→B = 0.3, B→A = 0.4, B→B = 0.6.
- First-observation likelihoods: A = 0.5, B = 0.1.
- Second-observation likelihoods: A = 0.1, B = 0.8.

Multiply each start value by its first likelihood. The time-one scores are A = 0.30 and B = 0.04. Keep both: the state with a smaller score now may lead to a stronger route later.

To reach A at time two, compare \(0.30\times0.7\times0.1=0.021\) from A with \(0.04\times0.4\times0.1=0.0016\) from B. Keep 0.021 and record A as its predecessor. That predecessor record is a backpointer.

To reach B, compare \(0.30\times0.3\times0.8=0.072\) with \(0.04\times0.6\times0.8=0.0192\). Keep 0.072 and a backpointer to A. The final best state is B; following its backpointer gives A→B.

A recurrence writes the repeated update as one rule:

\[D_t(s)=e_s(o_t)\max_r\{D_{t-1}(r)a_{rs}\}.\]

Here D is the best partial score, t is time, s is the new state, r is a previous state, a is a transition factor and e is the observation likelihood. Read it as: compare routes from every previous state, choose the largest, then multiply by the new observation likelihood.

For long sequences, multiplying many small numbers can underflow. Log scores turn products into sums. An impossible zero probability is represented by negative infinity in that convention. The forward algorithm sums incoming paths instead of taking the maximum, answering a different question. With continuous acoustic measurements, an emission may be a probability density rather than a discrete probability; density height is not itself the probability of an exact measurement.
EXAMPLE:: Two candidate paths for two observations have these supplied factors:

\[\begin{aligned}
P_A&=0.5\times0.8\times0.6\times0.7=0.168,\\
P_B&=0.5\times0.4\times0.9\times0.8=0.144.
\end{aligned}\]

The factors represent start probability, first observation likelihood, transition and second observation likelihood. Among these two candidates, \(P_A>P_B\). This is a joint-path comparison, not a complete recogniser or a normalised posterior over transcripts.
EXPLANATION:: We have compared two supplied joint path scores, not calculated a normalised posterior over every possible transcript. If several paths map to one transcript, the most likely single path and the highest summed transcript probability can disagree.
PITFALL:: The best alignment path is not necessarily the most probable transcript after summing all its possible alignments. State the decoding objective before interpreting the answer.

BRIDGE:: V21 introduced alignment: matching positions in audio with positions in text. This lesson uses a short symbol sequence, not a trained recogniser.
CONCEPT:: A speech recording contains many more time steps than written letters. CTC lets a model learn from the recording and its transcript without a hand-written letter label for every frame.
MECHANISM:: CTC uses blanks and repeated frame labels to handle different alignments. Merge adjacent repeats first, then remove blanks. Separating blanks can preserve repeated output letters.
TEACHING:: ### See the alignment problem

The word “book” may stretch across many audio frames. Different people may hold the vowel for different lengths of time. A transcript supplies the word but usually does not specify which frame belongs to each letter.

Connectionist temporal classification, or CTC, is a training method that allows many frame-level paths to represent the same final label sequence. It adds a special blank symbol meaning “emit no text label here”. Blank is not a literal space between words.

### Collapse a path in the right order

First merge labels that repeat immediately beside each other. Then remove the blanks. In the supplied path b b _ o o _ o k k, merging adjacent repeats gives b _ o _ o k. Removing blanks then gives “book”.

The blank between the two o groups matters. It stops them being merged into one o. If the path is b b o o k k with no separating blank, the result is “bok”.

### Understand what training adds up

Several different paths may collapse to the same transcript. CTC training adds their probabilities instead of demanding one manually selected frame alignment. The model still needs labelled recording–transcript pairs for this form of training.

Its standard formulation makes simplifying assumptions about frame outputs. Decoding may add a search procedure or language information. Do not assume that choosing the most likely label at each frame always finds the transcript with the greatest combined probability.

Merge adjacent repeats: b _ o _ o k
Remove blanks: b o o k → “book”.

Path: b b o o k k
Merge adjacent repeats: b o k
Remove blanks: “bok”.
A missing separating blank changes the repeated output label.

An encoder turns incoming audio features into internal representations. A decoder uses those representations and the text generated so far to predict the next text token. A token is a unit of model text; it may be a word, part of a word or another symbol.

The decoder repeats this process until it reaches a stopping condition. Its earlier predictions can influence later predictions, so one early error may affect the rest of a phrase.

“Reserve an atlas” and “reserve an actress” are both possible sequences of English words. Only one matches the fictional reference in the example. A recogniser has to use the audio to choose, rather than choosing solely by what reads smoothly.

A system may generate words for a silent or unclear section. This is often called hallucination: output that the input does not support. Treat a sentence such as “Thank you for watching” during a fictional silent segment as something to investigate, not as evidence that the speaker said it.

BRIDGE:: You can compare two short sentences and count words. V09 explained denominators. We will use supplied text, not run a speech model.
CONCEPT:: To improve a transcript system, inspect the mistakes it makes. Word error rate counts changed, missing and extra words relative to a reference transcript, but the kinds of mistakes matter too.
MECHANISM:: Count edits against a stated reference policy, combine counts correctly, and inspect which errors cause real problems. One overall WER does not describe every user experience.
TEACHING:: ### Align the reference and the prediction

The reference is the text you are using as the expected transcript. The hypothesis is the recogniser's proposed transcript. Align the two so you can identify substitutions, deletions and insertions.

A substitution changes an expected word. A deletion leaves one out. An insertion adds an extra word. Use a minimum-edit alignment: one requiring the fewest of those operations under the chosen rules.

### Calculate word error rate

In the example, “the” becomes “a” and “now” is added. There is one substitution, no deletion and one insertion. The reference has five words.

\[\mathrm{WER}=\frac{\text{substitutions + deletions + insertions}}{\text{reference word count}}\]

Two edits divided by five reference words is 40%. WER is not a probability that a sentence is wrong. Extra inserted words can even push it above 100%.

### Combine recordings using the counts

For two recordings with one edit each and reference lengths of 2 and 18 words, add the edits and reference words first. The combined rate is \(2/20=10\%\). Averaging the two recording percentages would give a different weighting.

### Find the mistakes that affect the product

A wrong person's name, a wrong amount and a missing polite word can each count as one edit. Their consequences can differ greatly. Group errors by meaning, noise, accent, device or other relevant conditions, while protecting speakers' privacy.

Use the same text-normalisation rules for each system: for example, explain how numbers and punctuation are handled. Include enough varied independent speakers to support group comparisons, and report uncertainty. A small or uneven sample can make a group rate unstable.

### Build the edit-distance table

Put reference prefixes down the rows and hypothesis prefixes across the columns. A prefix is the part from the start up to a chosen word. Cell D(i,j) stores the fewest edits needed to turn the first i reference words into the first j hypothesis words.

An empty reference needs j insertions, so the top row is 0, 1, 2 and so on. An empty hypothesis needs i deletions, so the first column is 0, 1, 2 and so on.

For each remaining cell, compare three candidates: the diagonal value plus zero for matching words or one for a substitution; the value above plus one for a deletion; and the value to the left plus one for an insertion. Keep the smallest. Record which candidate won if you want to reconstruct an alignment.

For reference [a] and hypothesis [a, b], the first matching-word cell is zero. The final cell is one because adding b needs one insertion. If several choices tie, document a consistent tie rule; equally minimal alignments can label individual edits differently.
EXAMPLE:: Reference: “please reserve the blue atlas” (five words). Hypothesis: “please reserve a blue atlas now”. A minimum alignment substitutes the→a and inserts now.

\[S=1,\quad D=0,\quad I=1,\quad N=5.\]

\[\mathrm{WER}=\frac{S+D+I}{N}=\frac25=40\%.\]

For two utterances with one error each and reference lengths 2 and 18:

\[\mathrm{WER}_{\text{corpus}}=\frac{1+1}{2+18}=10\%.\]

It is not the unweighted mean of the two utterance WERs.
EXPLANATION:: Both utterances contribute one edit, but their reference lengths differ. The aggregate weights reference words. WER can exceed 100% when insertions are numerous; it is an edit ratio, not a bounded probability that a transcript is wrong.
PITFALL:: Never describe 1 − WER as a universally valid accuracy probability. Insertion-heavy outputs can make it negative, and a word-level score does not represent task success or subgroup fairness by itself.

BRIDGE:: V29 separated acoustic representations from playable samples. V06 covered bits and powers. We will calculate the size of one invented coding scheme.
CONCEPT:: A vocoder makes waveform samples from another audio representation. A neural codec compresses audio into codes and reconstructs it. Understanding what each representation stores helps you reason about size, quality and delay.
MECHANISM:: Identify what the codes represent, count their payload explicitly, and check quality and delay separately. A smaller code stream is not automatically a faster or better voice system.
TEACHING:: ### Distinguish generating from compressing

A vocoder may generate a waveform from a mel spectrogram. A neural codec has an encoder that turns audio into a more compact representation and a decoder that reconstructs audio from it. The word encoder here refers to that compression stage, not necessarily an ASR encoder.

Some codecs represent each short frame with indices into learned tables. A table is called a codebook. An index selects an entry; it is not a text word or an original PCM sample.

### Count the indices

Our invented scheme produces 50 frames each second. Each frame uses four codebook indices. That gives 200 indices per second.

Each codebook has 1,024 entries. Since \(2^{10}=1024\), a fixed-width index needs ten bits. Multiply 200 indices by ten bits to obtain 2,000 bits per second. For three seconds, divide 6,000 bits by eight: 750 bytes of index data.

### State what that count leaves out

The calculation excludes headers and other metadata. A real codec can use different coding rules. Compression changes the representation and may lose information; fewer bits alone do not establish that speech quality is adequate.

### Keep bitrate and delay separate

Bitrate is how many bits are sent or stored per second of represented audio. Compute speed is how quickly a device performs the work. Algorithmic delay is how much audio the method must wait for before producing an output.

A low-bitrate method can still need substantial computation or future context. Check all three properties for a live conversation. Also check what an “audio token” means in the chosen system; that label is used for several different representations.

Open the paper on Watch & read to inspect a real architecture after finishing the invented bit count. Identify its actual frame rate, codebooks and delay before comparing it with the teaching example.

### Reconstruct a value using two codebooks

Residual quantisation uses a later codebook to approximate what the earlier one missed. Start with a made-up value 2.7 and codebook [0, 2]. Choose its nearest entry, 2, at index 1. Subtract: the residual is 0.7.

The next codebook is [0, 0.5, 1]. Its nearest entry to 0.7 is 0.5, also at index 1. Subtract again to leave about 0.2. Add the chosen entries to reconstruct 2.5. The indices are [1, 1]. Define how ties are resolved.

This one-number example explains the operation, not an actual learned audio codec. A learned vector codebook works with representations having several entries.

### Read the assigned architectures separately

The video introduces SemantiCodec; the main compression paper describes EnCodec. SemantiCodec's diagram includes a semantic encoder based on AudioMAE, quantisation with k-means, an acoustic encoder and a diffusion decoder. AudioMAE learns through reconstructing masked representations. K-means groups representations around selected centres. A diffusion decoder learns a guided noise-removal process; it does not promise exact recovery of every original sample.

A GAN instead trains a generator with a discriminator. The discriminator helps training and is not automatically the runtime encoder. Keep these different designs separate when reading their diagrams.

Cancellation asks a job to stop. It does not guarantee that every already-sent event disappears. Ask the recogniser, model or synthesiser to stop where supported; also remove queued, unplayed audio belonging to the old response.

Those 20 exchanges may suggest an idea worth further study. They do not yet show that spontaneous conversation improves for varied users.

### Read results with their conditions

Check speaker and session separation, language coverage, hardware, latency definitions and uncertainty. A comparison can change because of a different input set or compute budget rather than the proposed method.

Use equations to answer a particular question about the method. Define the symbols and trace a tiny example before moving to the full notation. Keep a list of concepts to study instead of treating an unfamiliar symbol as a reason to stop reading.

Do not invent a result when a paper omits it. Record exactly what you could and could not verify from the text, appendix and available artifacts.
