BRIDGE:: Start here. You need no programming or audio background. Keep a notebook with three columns: the claim, the evidence and the question still open. The next four topics teach the computing tools used later.
CONCEPT:: Voice AI helps computers work with speech and other sounds. You might use it to write down what someone says, speak an answer aloud or compare a voice with an identity claim. These are different tasks: having a microphone does not mean a system can do all of them.
MECHANISM:: Follow a typical request through the app. The microphone captures audio. Automatic speech recognition (ASR) proposes the words. A dialogue component decides what to ask or do next. Text-to-speech (TTS) creates a spoken reply. The transport layer carries messages between these parts. Your app must also check permissions, handle failures and stop work when it is cancelled. Direct speech-generation systems need someone to handle these jobs too.
TEACHING:: Begin with the user's task. “Help me change an appointment” is a task; “use a large model” is a design choice. Write what success means before selecting components: the correct appointment changes, the user confirms it, and a failed connection does not create a duplicate booking.

Draw the information flow. Audio contains more than words: pauses, overlap, emphasis and background sound can matter. Text may discard some of that information. A component output is a proposal with limitations, not automatically a fact or an authorised action.

Now draw the control flow: the rules that decide what happens next. Who decides that the user has finished speaking? Who stops playback when they interrupt? Who checks permission to change a calendar? Even a good speech model can seem unreliable if the app stops listening too early or keeps speaking after an interruption. You will study both the audio models and the rules around them.

Application: validate account, event ownership and explicit confirmation.

CONCEPT:: A program follows rules to store values and calculate results. A function groups a useful set of instructions under a name so you can reuse it. For example, you can write one function to turn a sample count into seconds, then call it with different recordings. Start by saying what goes in, what comes out and which inputs are allowed.
MECHANISM:: Python calculates an expression and can store its result in a variable. When you call a function, you pass it inputs called arguments. A return statement sends a result back to the caller so other code can use it. Print displays a value for a person; it does not do the same job as return. Numbers and text behave differently, so choose conversions deliberately.
TEACHING:: Read a program from top to bottom, but remember that a function body runs only when called. In the example, def introduces a function. The indented lines belong to it. samples and rate are parameters: local names for the values supplied by a caller.

Division converts a sample count into seconds when the rate is samples per second. Writing the unit beside a variable in your notebook prevents a common error: confusing a count with a duration. A useful function returns the result so other parts of a program can use it.

An if statement selects a branch. Raising ValueError makes an invalid input explicit instead of producing a plausible but meaningless duration. This introductory version accepts ordinary numeric inputs; later topics add stronger input contracts and tests. Do not infer that it already handles every possible Python object.

Trace names and types explicitly. In samples = 32000, the equals sign assigns a value; it does not ask whether two things are equal. == tests equality. The integer 16000 is a number; "16000" is text. Python evaluates 32000 / 16000 numerically, but joining text and multiplying a duration require deliberate conversions. A function's parameters are local names: changing the caller's variable name does not change the function's meaning.

Read the Boolean condition as two failure cases joined by or. A negative sample count is invalid even with a good rate; a zero rate is invalid even with a good count. The colon starts an indented block. Four spaces make the example easy to read. After a return, that function call is finished. Run each invalid call separately or catch its exception; an uncaught error stops the rest of the script, so the later print statements will not run.
EXAMPLE:: # Save as duration.py and run with Python 3.
def duration_seconds(samples, rate):
    if samples < 0 or rate <= 0:
        raise ValueError("Expected non-negative samples and positive rate")
    return samples / rate

seconds = duration_seconds(32000, 16000)
print(seconds)                 # 2.0
print(duration_seconds(0, 16000))  # 0.0
EXPLANATION:: The first call divides 32,000 by 16,000, giving two seconds. The second has no samples, so its duration is zero. Replacing return with print would display a number but return None; the caller could no longer safely use the duration in a calculation.
PITFALL:: Variable names do not enforce units or types. A variable called rate can still contain the string “fast”. Clear names help people, but validation and tests establish behaviour.
EXERCISE:: Predict both printed values before running the example. Add calls for 8,000 samples at 16,000 samples/second and 48,000 at 48,000. Write the expected result and unit for each. Then call the function with rate zero and explain the exception. Finally write milliseconds(samples, rate), reusing duration_seconds and multiplying by 1,000.
SOLUTION:: The original prints are 2.0 and 0.0 seconds; the added durations are 0.5 and 1.0 seconds. Define the reusable conversion after duration_seconds:

```python
def milliseconds(samples, rate):
    return duration_seconds(samples, rate) * 1000

print(milliseconds(8000, 16000))  # 500.0
```

A rate of zero raises ValueError before division. Run that invalid call last or separately, because an uncaught exception stops the file. Return supplies a value to the caller; print only displays it.
CHALLENGE:: Without copying the function body, write remaining_seconds(total_samples, consumed_samples, rate). Reject consumed counts below zero or above the total. Demonstrate 32,000 total and 8,000 consumed at 16,000/second, plus one rejected case.
CHALLENGE_SOLUTION:: Add the following below duration_seconds. The supplied contract is ordinary numeric counts/rate; it does not accept text or establish a complete type schema.

```python
def remaining_seconds(total_samples, consumed_samples, rate):
    if consumed_samples < 0 or consumed_samples > total_samples:
        raise ValueError("consumed count is outside the total")
    return duration_seconds(total_samples - consumed_samples, rate)

print(remaining_seconds(32000, 8000, 16000))  # 1.5
# Run separately as a rejected case:
# remaining_seconds(32000, 40000, 16000)
```

The rejected call asks to consume more than exists. The reused function also rejects an invalid rate.
QUESTION:: Why return a duration instead of only printing it?
CORRECT:: The caller can use the returned value in another calculation or test.
WRONG1:: Printing changes a string permanently into a number.
WRONG2:: A printed number automatically becomes every function's return value.
FEEDBACK:: Return connects functions through values. Print writes to an output stream and does not replace a useful return contract.

ID:: V03
BRIDGE:: V02 introduced functions and numeric values. This topic adds branching and repetition. This topic uses lists to hold sequences and dictionaries to name fields. Work with supplied fictional events, not recordings or live services.
CONCEPT:: A collection stores related values together. Instead of naming each audio event separately, you can keep the events in a list and use a loop to examine them one at a time. The collection stores the information; the loop repeats the work. In a streaming system, the order of those events often matters.
MECHANISM:: A list keeps items in order. A dictionary connects a key, such as kind, to a value, such as speech. A for loop visits the items. To add their durations, start a running total at zero and update it for each item; this running total is an accumulator. Indentation shows which instructions belong inside the loop or a decision branch.
TEACHING:: First establish the event contract. Every event below contains a kind and a duration in milliseconds. The function checks that duration is non-negative before using it. Rejecting invalid data early keeps an impossible duration from quietly corrupting totals.

Trace the loop by hand. On the first speech event, total increases by 120. A silence event leaves total unchanged. The last speech event adds 80. A dictionary makes the meanings visible, whereas a list like [1,120] would require a separate explanation of what each position means.

This function deliberately measures durations already labelled by someone else. It does not recognise speech or decide whether those labels are correct. Separating a deterministic calculation from uncertain model output makes failures easier to locate.

A concrete dictionary lookup is events[0]["kind"]. events[0] selects the first event because list positions start at zero; the second lookup selects its kind field. A dictionary key is a name, not a position. Accessing a missing key raises KeyError. An empty list contains no events, while a list containing one empty dictionary contains an event with missing information; these are different inputs.

Use if/elif/else to select exactly one duration bucket. Initialise a dictionary such as {"speech_ms": 0, "silence_ms": 0, "other_ms": 0}; add duration to one key per event. total += duration means total = total + duration. Keep the return after the loop: placing it inside would stop after the first event. Check the invariant speech_ms + silence_ms + other_ms equals the sum of all accepted event durations.

range(3) yields 0, 1 and 2; it is a range object rather than a list and excludes the stop. while needs a changing condition or a reachable exit. break exits the innermost loop and return exits the function. A missing key and a key holding None are different. raise ValueError("Negative duration") stops the current calculation with a named error instead of returning an invalid total; handling such errors is introduced in V04.
EXAMPLE:: def speech_ms(events):
    total = 0
    for event in events:
        duration = event["duration_ms"]
        if duration < 0:
            raise ValueError("Negative duration")
        if event["kind"] == "speech":
            total += duration
    return total

events = [
    {"kind": "speech", "duration_ms": 120},
    {"kind": "silence", "duration_ms": 50},
    {"kind": "speech", "duration_ms": 80},
]
print(speech_ms(events))  # 200
EXPLANATION:: The running total is 120, then 120, then 200. The complete timeline lasts 250 milliseconds, but labelled speech occupies 200. Those are different quantities. An empty list returns zero because the loop never changes the accumulator.
PITFALL:: Counting events is different from adding durations. Three short events can occupy less time than one long event. Similarly, a label named speech is supplied evidence, not proof of a detector's accuracy.
EXERCISE:: Make a table with event index, kind, duration and running speech total. Add a silence event lasting 300 milliseconds and predict both speech time and total timeline time. Then replace the first duration with -1 and explain where execution stops. Write a second function that totals all event durations.
SOLUTION:: The extra silence leaves speech time at 200 ms and raises total timeline time from 250 to 550 ms. A negative first duration raises before any later event. This total-duration function retains the same numeric contract:

```python
def total_ms(events):
    total = 0
    for event in events:
        duration = event["duration_ms"]
        if duration < 0:
            raise ValueError("Negative duration")
        total += duration
    return total
```

Calling total_ms([]) returns 0 because the loop has no iterations. The label kind does not affect this total.
CHALLENGE:: Implement a summary returning a dictionary with speech_ms, silence_ms and other_ms. Treat unknown kinds as other rather than silently discarding their time. For speech 40, silence 20 and music 30, supply the expected dictionary and total-duration invariant.
CHALLENGE_SOLUTION:: A complete reference using the supplied valid event shape is:

```python
def summary(events):
    totals = {"speech_ms": 0, "silence_ms": 0, "other_ms": 0}
    for event in events:
        duration = event["duration_ms"]
        if duration < 0:
            raise ValueError("Negative duration")
        if event["kind"] == "speech":
            key = "speech_ms"
        elif event["kind"] == "silence":
            key = "silence_ms"
        else:
            key = "other_ms"
        totals[key] += duration
    return totals
```

For speech 40, silence 20 and music 30, the result is {"speech_ms":40,"silence_ms":20,"other_ms":30}. Their sum is 90, equal to all supplied durations. This checks dropped time, not label accuracy.
QUESTION:: What does the speech_ms function establish?
CORRECT:: The summed duration of events already labelled speech under its input contract.
WRONG1:: Whether each event really contains human speech.
WRONG2:: The number of words spoken in the audio.
FEEDBACK:: The function performs arithmetic on supplied labels. Detecting speech and recognising words are separate responsibilities.

BRIDGE:: V03 handled in-memory event lists. Now preserve structured data and check deterministic behaviour. Use a fresh practice folder. The example uses Python's standard library and does not open a network connection.
CONCEPT:: Files keep your data after a program stops. Tests record what you expect your code to do, then check whether it does that. If an input breaks a rule, a clear error helps you find the problem. Quietly continuing with a wrong result makes the problem harder to notice.
MECHANISM:: JSON is a text format for objects, arrays, strings, numbers, booleans and null. Python’s json.loads turns that text into Python values. A test checks those values against an answer you chose from the requirement, not by copying the program’s current output. You can also test that an invalid input raises the expected exception.
TEACHING:: Distinguish decoding from validation. Valid JSON such as an empty object may still lack the fields your application requires. Validate required fields and value ranges before calculating. Use explicit exceptions for invalid inputs; an assertion is appropriate in a test but should not enforce production input validation because Python can disable assertions.

Keep pure calculations separate from file access. A function that receives already-decoded data is easy to test with tiny examples. A thin outer layer can later read a file and report its name if decoding fails. Avoid catching every exception and returning zero, which would make broken input look like a successful empty recording.

A good test has a reason to fail. Include a normal example, a boundary such as an empty list, and an invalid example. The expected answer should come from your hand calculation, not from calling the same function a second time.

Read the video cards in this order: exceptions, modules/JSON, file access, then unit tests. import json makes a module available; json.loads decodes text, json.load reads an open text file, json.dumps creates JSON text and json.dump writes it. response.json() in the historical video returns decoded Python values, not formatted JSON. Observe the web-request code only; use our local fictional fixture. sys.argv is a list of command-line strings, with the script name at position zero, but no network or command-line API exercise is required.

Importing can execute module-level statements, even when using from ... import. if __name__ == "__main__": guards work intended only when that file is run directly; it does not protect other top-level statements. EXAMPLE:: import json

def total_ms(events):
    result = 0
    for event in events:
        value = event["duration_ms"]
        if type(value) is not int or value < 0:
            raise ValueError("duration_ms must be a non-negative integer")
        result += value
    return result

data = json.loads('[{"duration_ms": 20}, {"duration_ms": 35}]')
assert total_ms(data) == 55
assert total_ms([]) == 0
assert total_ms([{"duration_ms": 20}, {"duration_ms": 35}]) == 55

except ValueError:
    pass
else:
    raise AssertionError("Negative duration was accepted")

Missing keys still raise KeyError, an explicit limit of this introductory contract. No speech model is loaded or assessed.

ID:: V06
BRIDGE:: V02 used division to convert samples to time. Before studying waves or learning algorithms, practise rearranging equations, tracking units and interpreting powers. Use pencil and paper or an ordinary calculator.
CONCEPT:: Algebra helps you work out relationships, such as how a sample rate and recording length determine the number of samples. Units tell you whether a number means seconds, bytes or something else. Powers describe repeated multiplication; logarithms let you work backwards from the result to the exponent. You will use all four ideas to reason about audio.
MECHANISM:: If N = rate × duration, dividing both sides by rate gives duration = N/rate. A logarithm answers an exponent question: \(\log_{10}(1000)=3\) because 10 cubed is 1000. Decibels express a ratio on a logarithmic scale; the formula depends on whether the ratio describes power or an amplitude measured under matching conditions.
TEACHING:: Always write the unit before substituting numbers. A rate of 16 kHz means 16,000 samples each second, not 16 samples. Milli means one thousandth; kilo means one thousand. Converting 250 milliseconds gives 0.25 seconds, so one channel at 16,000 samples/second contains 4,000 samples in that interval.

Bit depth describes bits per sample per channel in uncompressed PCM. Multiplying rate, duration, channels and bits/sample gives a bit count. Dividing by eight converts bits to bytes. Headers, container metadata and compression are separate, so this is an audio-payload calculation.

For a power ratio P2/P1, decibels equal \(10\log_{10}(P_2/P_1)\). For matching impedance and comparable amplitude definitions, power is proportional to amplitude squared, giving \(20\log_{10}(A_2/A_1)\). A digital amplitude ratio is not automatically a calibrated sound-pressure level near someone's ears.

Algebra bridge: an equation keeps two quantities equal. If \(B=f_sTCb/8\), isolate seconds by multiplying both sides by 8 and dividing by the other positive factors. For 64000 bytes at 16000 Hz, mono and 16 bits, \(T=\frac{64000\times8}{16000\times1\times16}=2\ \mathrm{s}\). Parentheses matter: divide by the complete denominator, not only its first number.

A power means repeated multiplication: \(2^3=8\). A negative exponent reverses it: \(2^{-3}=\frac18\). A logarithm asks for an exponent: \(\log_{10}(1000)=3\) because \(10^3=1000\). Natural logs use base e, approximately 2.718; \(\ln(e^2)=2\). For positive a and b, \(\log(ab)=\log(a)+\log(b)\). This turns a product of small probabilities into a sum of logs in V21. Zero has no finite logarithm; a log floor is an explicit approximation, not evidence that zero was positive.

Check yourself before V08/V15: solve \(3x+2=14\) by subtracting two then dividing by three (\(x=4\)); explain \(10^{-2}=0.01\); convert 20 ms to 0.020 s. If these steps are unfamiliar, complete the assigned algebra/logarithm tutorial exercises before proceeding.
EXAMPLE:: For uncompressed PCM payload, let \(f_s\) be samples/second, \(T\) seconds, \(C\) channels and \(b\) bits/sample/channel. Headers and compression are excluded.

\[\begin{aligned}
B&=\frac{f_sTCb}{8}\\
 &=\frac{16{,}000\times2\times1\times16}{8}\\
 &=64{,}000\ \text{bytes}.
\end{aligned}\]

Under the stated comparable-amplitude/impedance assumptions:

\[\begin{aligned}
20\log_{10}(2)&\approx6.02\ \mathrm{dB}\quad\text{(amplitude ratio)},\\
10\log_{10}(2)&\approx3.01\ \mathrm{dB}\quad\text{(power ratio)}.
\end{aligned}\]
EXPLANATION:: The two decibel answers differ because amplitude and power are different quantities. The payload is 64,000 decimal bytes; this does not include the file header. A stereo recording at the same rate and depth doubles the payload because it stores two channels.
PITFALL:: A value in dB needs a ratio or reference. “The audio is 60 dB” is incomplete unless the measurement and reference are specified. Do not turn digital sample values into hearing-safety claims.
EXERCISE:: Calculate the payload for 0.5 seconds of stereo PCM at 48 kHz and 16 bits/sample. Show every conversion. Then find the duration of 24,000 mono samples at 16 kHz. Explain the difference between doubling amplitude and doubling power in the stated matching conditions.
SOLUTION:: Payload is \(48{,}000\times0.5\times2\times16/8=96{,}000\) bytes. Duration is \(24{,}000/16{,}000=1.5\) seconds. Doubling amplitude corresponds to four times the power and about +6.02 dB; doubling power is about +3.01 dB.
CHALLENGE:: A specification says “one minute, 16 kHz, 16-bit, mono, under 1 MB uncompressed”. Check the claim using decimal MB and show how long one million payload bytes can hold, excluding a header.
CHALLENGE_SOLUTION:: One minute is 60 seconds, so the PCM payload is \(16{,}000\times60\times1\times16/8=1{,}920{,}000\) bytes, exceeding one decimal MB. Payload rate is \(16{,}000\times1\times16/8=32{,}000\) bytes/second. One million payload bytes therefore holds \(1{,}000{,}000/32{,}000=31.25\) seconds, excluding a header. Revise the requirement or choose a documented compression format; renaming the file does not change its representation.
QUESTION:: Which formula gives uncompressed PCM payload bytes?
CORRECT:: Sample rate × duration × channel count × bits per sample ÷ 8.
WRONG1:: Sample rate ÷ duration, regardless of channels.
WRONG2:: Duration × decibels, because louder audio always uses more bytes.
FEEDBACK:: PCM payload size follows the number and representation of stored samples, not the signal's loudness.

ID:: V07
BRIDGE:: V06 established arithmetic and units. A vector is simply an ordered collection of numbers; a matrix is a rectangular table. You do not need to have studied tensors before this lesson. Work through the tiny shapes before moving to the assigned linear-algebra course.
CONCEPT:: A vector is an ordered list of numbers, and a matrix is a table of numbers. They let you describe calculations on many audio measurements at once. A model can turn one vector into another using a matrix. Before calculating, check the shape: how many entries or rows and columns should each input and output have?
MECHANISM:: A dot product multiplies matching vector entries and adds the results. Matrix multiplication applies many dot products. If a matrix has shape m by n and a column vector has n entries, the result has m entries. A tensor generalises an array to additional axes; each axis needs a meaning, such as batch, time or feature.
TEACHING:: Start with a two-feature frame. The numbers might describe energy and a spectral measurement after a documented normalisation. A weight vector combines them into one score. The order matters: swapping feature positions without swapping weights changes the function.

For multiple scores, put one weight vector in each matrix row. Each row produces one output. Bias adds a constant to each output after the multiplication. A linear layer alone cannot express every relationship; nonlinear transformations arrive in V18.

Shapes are not enough to guarantee meaning. Two arrays can both have length two while representing different units or feature orders. Record the axis names and preprocessing contract alongside dimensions. Never “fix” a mismatch by reshaping until the multiplication happens without understanding which axis moved.

A dot product multiplies matching coordinates then adds: \([1,2]\cdot[3,4]=1\cdot3+2\cdot4=11\). It is defined for equal-length vectors. The squared length of [3,4] is its self-dot-product, 25; its length is \(\sqrt{25}=5\). Dividing each coordinate by five gives a unit-length vector [0.6,0.8]. A zero vector cannot be normalised this way because its length is zero.

Orthogonal vectors have dot product zero: \([1,1]\cdot[1,-1]=0\). In V15 this gives a way to separate signal patterns; in attention, dot products give matching scores. Similarity is still representation-dependent: a large score from badly scaled features may reflect scale rather than meaning. Broadcasting is a library rule for extending compatible shapes; it is not permission to ignore axis meanings. Before library-based work, complete the assigned matrix exercises by hand and label every axis.
EXAMPLE:: Use a column-vector convention. The input and bias have shape \((2,1)\); the weight matrix has shape \((2,2)\).

\[\mathbf{x}=\begin{bmatrix}2\\3\end{bmatrix},\quad
W=\begin{bmatrix}1&2\\-1&1\end{bmatrix},\quad
\mathbf{b}=\begin{bmatrix}0\\4\end{bmatrix}.\]

\[\begin{aligned}
\mathbf{y}&=W\mathbf{x}+\mathbf{b}\\
&=\begin{bmatrix}1\cdot2+2\cdot3+0\\-1\cdot2+1\cdot3+4\end{bmatrix}
=\begin{bmatrix}8\\5\end{bmatrix}.
\end{aligned}\]

A batch of four clips, each with 100 frames and 80 features per frame, has shape \((4,100,80)\) when the axes are batch, time, feature.
EXPLANATION:: Each matrix row consumes both input features. The bias does not change the output shape. The three-axis example has 32,000 numeric entries, but says nothing about their numeric precision, sampling rate or physical duration unless the frame construction is also defined.
PITFALL:: A shape-compatible operation can still combine the wrong quantities. Broadcasting can silently repeat values across an unintended axis. Name and check each axis before interpreting a result.
EXERCISE:: Recalculate the example for x = [1, 0]. Then write a matrix that turns [left, right] into [left + right, left - right]. Apply it to [3, 1]. Finally explain why a (3, 4) matrix cannot multiply a (5, 1) column vector.
SOLUTION:: The first result is [1, 3]. The sum/difference matrix is \(\begin{bmatrix}1&1\\1&-1\end{bmatrix}\), producing [4,2]. In the invalid multiplication, the inner dimensions 4 and 5 do not match. This is a structural error, not a rounding problem.
CHALLENGE:: A model receives \((8,50,40)\) with batch/time/feature axes. It applies a 12-output linear layer independently at each time step. State the weight shape, output shape, number of weights and number of biases. Explain what would change if time and feature were accidentally swapped.
CHALLENGE_SOLUTION:: Under the column-vector rule y=W x+b from the example, weights have shape \((12,40)\), output (8,50,12), with 480 weights and 12 biases. Swapping time and feature changes the last-axis length to 50 and makes the existing weights incompatible; rebuilding weights would define a different function over time positions, not repair the original meaning. A library using row vectors \(y=xW+b\) stores weights as \((40,12)\); the same 480 coefficients are transposed. State the convention before comparing shapes.
QUESTION:: What must agree in ordinary matrix multiplication?
CORRECT:: The left matrix's column count and the right matrix's row count.
WRONG1:: Only the total number of values in the two arrays.
WRONG2:: Every axis must have the same size.
FEEDBACK:: Inner dimensions align the entries used by each dot product. Matching dimensions still requires matching semantic axes.

ID:: V08
BRIDGE:: V06 introduced equations and V07 introduced vectors. A derivative measures how an output changes when an input changes slightly. The graduate material uses calculus repeatedly; complete the assigned calculus units if the chain rule remains unfamiliar after this example.
CONCEPT:: When you train a model, you adjust its parameters to reduce a chosen error measure, called the loss. A gradient tells you which nearby direction increases that loss fastest. Gradient descent takes a small step the other way. Each step uses information near the current parameters; it does not guarantee that you will find the best possible model.
MECHANISM:: For \(L(w)=(w-3)^2\), the derivative is \(L'(w)=2(w-3)\). Gradient descent updates \(w_{\mathrm{new}}=w-\eta L'(w)\), where \(\eta\) is the learning rate. With several parameters, compute one partial derivative per parameter. The chain rule connects derivatives through composed functions, enabling neural-network training.
TEACHING:: Understand the loss before the update. Squaring the distance from three makes all errors non-negative and gives a minimum at three. If w is below three, the derivative is negative; subtracting a negative number increases w toward three. If w is above three, the direction reverses.

The learning rate controls step size. Too small may progress slowly; too large may overshoot or diverge. A decreasing training loss says the parameters fit the training objective better. It says nothing by itself about independent examples, subgroup performance or the suitability of the objective.

For a composition, track intermediate variables. If z = 2w and L = (z − 6)², then \(\frac{dL}{dz}=2(z-6)\), \(\frac{dz}{dw}=2\) and \(\frac{dL}{dw}=4(z-6)\). Omitting a chain-rule factor changes the update even when the code still runs.

A derivative is a local rate of change. Around w = 1, \(L(w)=(w-3)^2\) has slope about −4: a small positive change in w lowers this loss. The finite-difference quotient compares losses at nearby points and divides by their separation. It approximates a derivative; rounding and step size affect its accuracy. The derivative is not the loss itself and does not promise that a large step helps.

For multiple parameters, a partial derivative varies one parameter while holding the others fixed. For \(L(a,b)=(a-1)^2+2(b+2)^2\), the gradient is \([2(a-1),4(b+2)]\). At (0,0) that is \([-2,8]\). A simultaneous step of 0.1 gives \((0.2,-0.8)\), so the loss drops from 9 to \(0.64+2.88=3.52\). Compute all gradients at the old point before updating; mixing old and new coordinates implements a different procedure. V18 uses this same bookkeeping through a chain of intermediate values.

Before the calculus clips, recall that a function maps an input to an output and composition feeds one result into another. A line through \((x_0,y_0)\) with slope \(m\) has equation \(y-y_0=m(x-x_0)\). The derivative, when this limit exists, is

\[f'(x)=\lim_{h\to0}\frac{f(x+h)-f(x)}{h}.\]

Use nonzero \(h\) while simplifying; setting \(h=0\) in the original quotient gives an undefined division. For \(f(x)=x^2\), expansion gives \(((x+h)^2-x^2)/h=2x+h\), whose limit is \(2x\). The recitation's rational example uses the same idea with a common denominator. A tangent is a local limiting slope, not necessarily a line that touches the curve at only one point.

The chain-rule clips use trigonometry as an example. On a unit circle, cosine is the horizontal coordinate and sine the vertical coordinate of an angle measured in radians; one full turn is \(2\pi\) radians. Take the identities \(d(\sin t)/dt=\cos t\) and \(d(\cos t)/dt=-\sin t\) as supplied rules for those examples. The power rule is \(d(t^n)/dt=nt^{n-1}\) for the positive-integer powers used here. Thus \(\sin^{10}t\) means \((\sin t)^{10}\), whereas \(\sin(10t)\) changes the angle. Their derivatives are \(10(\sin t)^9\cos t\) and \(10\cos(10t)\), respectively. The intermediate-variable method explains the different factors; treating derivative notation as fractions that can always be cancelled is insufficient. A zero derivative identifies a stationary point, not automatically a maximum or minimum. The supplied polynomial exercise does not require a trigonometry course first.
EXAMPLE:: Start with a scalar squared loss, step size \(\eta=0.1\), and initial parameter \(w_0=0\).

\[L(w)=(w-3)^2,\qquad L'(w)=2(w-3).\]

\[\begin{aligned}
w_1&=w_0-\eta L'(w_0)=0-0.1(-6)=0.6,\\
L(w_1)&=(0.6-3)^2=5.76,\\
w_2&=0.6-0.1(-4.8)=1.08,\\
L(w_2)&=(1.08-3)^2=3.6864.
\end{aligned}\]

A central finite-difference check near \(w=1\) gives:

\[\frac{L(1.001)-L(0.999)}{0.002}\approx-4.\]
EXPLANATION:: The finite difference estimates slope by comparing nearby points. It is a check on this small calculation, not a substitute for a general proof or an instruction to launch a model experiment. All quantities are supplied, so pencil-and-paper reasoning is sufficient.
PITFALL:: A lower loss does not establish that a speech system understands a request. It only describes the chosen objective on the data used to compute it. Generalisation and useful behaviour require separate evidence.
EXERCISE:: Starting from w = 5 with rate 0.1, calculate two updates and their losses. Repeat the first update with rate 1.2. Explain what the comparison shows about step size. Then differentiate \(L(w)=(2w-6)^2\) using the chain rule.
SOLUTION:: From five, the updates are 4.6 then 4.28, with losses 2.56 and 1.6384. At rate 1.2, the first new value is 0.2 and loss is 7.84, worse than the original loss four. The composed derivative is \(4(2w-6)\), equivalently \(8w-24\).
CHALLENGE:: For \(L(a,b)=(a-1)^2+2(b+2)^2\), start at (3,−1) with rate 0.1. Compute the gradient, one update and the old/new loss. State why one successful update is not a universal convergence argument.
CHALLENGE_SOLUTION:: The gradient is \((2(a-1),4(b+2))=(4,4)\). Subtract 0.1 times each component to get \((2.6,-1.4)\). Old loss is \(4+2=6\); new loss is \(1.6^2+2(0.6^2)=3.28\). This quadratic and step behaved well once. Different curvature, non-convex losses and step sizes can behave differently; one observed decrease does not prove convergence.
QUESTION:: What does the gradient-descent update subtract?
CORRECT:: The learning rate multiplied by the gradient of the chosen loss.
WRONG1:: The loss itself from every parameter, regardless of its derivative.
WRONG2:: A fixed amount of audio from the input waveform.
FEEDBACK:: A loss value measures error; its gradient describes local parameter sensitivity. They play different roles.

ID:: V09
BRIDGE:: V06 provides fractions and powers. This topic introduces uncertainty with small counts. No prior statistics is assumed. Keep population claims separate from the tiny fictional samples used for arithmetic practice.
CONCEPT:: Probability describes how uncertain an outcome is under stated assumptions. Statistics helps you learn from observations. Before trusting an average or percentage, ask: “What did we count? Who or what did we sample? Whom should this result describe?” Those questions matter as much as the calculation.
MECHANISM:: A conditional probability restricts attention to a stated condition: \(P(\mathrm{error}\mid\mathrm{noisy})\) means the error rate among noisy examples. The mean adds values and divides by their count. Variance describes spread around that mean. Independent sampling assumptions and sample size affect uncertainty; many near-duplicate clips are not many independent speakers.
TEACHING:: Define the denominator first. If two of ten noisy clips contain a transcription error, the observed clip-error proportion is \(2/10\). It is not a word-error rate, because the unit is clips. It also does not estimate performance for every language or microphone.

Conditioning changes a question. \(P(\mathrm{error}\mid\mathrm{noisy})\) and \(P(\mathrm{noisy}\mid\mathrm{error})\) need different denominators. Bayes' rule connects these probabilities when the relevant base rates are known. Ignoring how common each condition is can produce misleading conclusions.

Summaries can hide distribution shape. The mean latency of 100,100,100,100,600 milliseconds is 200, while the median is 100. A user encountering the long delay experiences something the mean alone conceals. Report counts, spread, a clearly defined percentile convention and relevant grouping, rather than one attractive number.

Build spread from a small example. For latencies [100,100,400] ms, the mean is 200 ms. Deviations are [-100,-100,200] ms; squared deviations are [10000,10000,40000] ms². Dividing their sum by three gives the population variance of this supplied list, 20000 ms². Its square root is about 141.4 ms. When estimating a population variance from an independent sample, the usual sample formula divides by n−1 instead, yielding 30000 ms² here. State which quantity you mean.

Distinguish two questions: “How spread out are these observations?” and “How uncertain am I about the mean I estimated?” With suitable independent sampling, more independent units generally reduce uncertainty about the mean. Many similar clips from one speaker do not give you the same evidence as many independent speakers.

To understand a confidence interval, imagine taking many new samples in the same way and calculating an interval from each. Under the procedure’s assumptions, its stated coverage describes how often those intervals would contain the true population value being estimated. This is repeated-sampling coverage. It does not promise what will happen for one future user. Work through the assigned exercises on random variables, expectation, variance and sampling before interpreting a paper’s uncertainty claims. The small calculations here give you a starting point.

A population is the group a claim concerns; a sample is the set measured. A histogram groups values into bins; inspect whether its vertical scale shows counts or density and whether bin widths vary. A normal distribution is a symmetric bell-shaped density model with mean \(\mu\) and standard deviation \(\sigma\); probabilities are areas, not heights at individual points. Computing descriptive mean and variance does not require normality. Under independent, identically distributed sampling with finite variance, division by \(n-1\) makes the usual sample variance unbiased; its square root is not generally an unbiased estimate of population standard deviation.
EXAMPLE:: Fictional labelled clip counts (the unit is clips, not words):

\[\begin{array}{l|rr|r}
&\text{Error}&\text{No error}&\text{Total}\\\hline
\text{Noisy}&6&14&20\\
\text{Quiet}&4&76&80\\\hline
\text{Total}&10&90&100
\end{array}\]

\[\begin{aligned}
P(\text{error}\mid\text{noisy})&=\frac{6}{20}=0.30,\\
P(\text{noisy}\mid\text{error})&=\frac{6}{10}=0.60,\\
\widehat p_{\text{error}}&=\frac{10}{100}=0.10.
\end{aligned}\]
EXPLANATION:: The overall rate is dominated by quiet clips because they form 80% of this sample. A deployment with a different noise mix can have a different overall rate even if each conditional rate stays unchanged. None of these counts establishes causation by itself.
PITFALL:: A large number of correlated frames does not create a large independent sample. Speaker, session and recording-device dependence can make naive uncertainty estimates much too confident.
EXERCISE:: For a fictional deployment containing 50 noisy and 50 quiet clips, assume the conditional rates above remain unchanged. Calculate the expected number with errors and the overall expected rate. Then calculate the mean and median of the five supplied latencies. State two assumptions behind the error prediction.
SOLUTION:: Expected errors are \(50(0.30)+50(0.05)=17.5\), an expected rate of 17.5%; an expectation need not be an integer observed count. Mean latency is 200 ms and median is 100 ms. The calculation assumes the conditional rates transfer and that the categories and error definitions remain comparable.
CHALLENGE:: One report counts 1,000 clips from two speakers; another counts 200 clips from 200 speakers. Explain why clip count alone cannot decide which better supports a claim about new speakers. Propose the missing sampling information and a sensible grouping for uncertainty analysis.
CHALLENGE_SOLUTION:: The first report has many within-speaker observations but little speaker diversity. The second may better address new-speaker transfer, but selection, languages, clip difficulty and session independence still matter. Ask for speaker/session distributions and the target population. Group uncertainty calculations at an appropriate independent unit, often speaker or session, and describe the assumptions.
QUESTION:: In the supplied table, what is \(P(\mathrm{noisy}\mid\mathrm{error})\)?
CORRECT:: \(6/10\), because the denominator is all error clips.
WRONG1:: \(6/20\), because the denominator is all noisy clips.
WRONG2:: 20/100, because the overall noisy proportion answers every conditional question.
FEEDBACK:: Conditioning defines the subset you count within. Reversing the condition usually changes the probability.

ID:: V10
BRIDGE:: V04 supplied deterministic tests and V09 supplied sampling concepts. This lesson is about planning and critiquing studies using fictional records. It does not ask you to train a model, call a provider or run an evaluation harness.
CONCEPT:: A fair test uses information that would actually be available when the system is used. Data leakage happens when information slips across that separation. For example, clips from the same speaker in both training and testing can make recognition look better than it would for a new speaker. Design the comparison around the claim you want to make.
MECHANISM:: Training data fit parameters. Validation data support choices such as thresholds and model selection. A held-out test set estimates performance after those choices are fixed. Splitting at clip level may leak speaker or session characteristics across sets. The split unit should reflect what is genuinely new in the target use case.
TEACHING:: Write the deployment question first. “Works for a new utterance from a known speaker” is different from “works for an unseen speaker in another clinic”. These claims require different separation boundaries and representative data. A random split is not automatically the right split.

Keep preprocessing within the boundary. A normalisation mean computed using held-out examples leaks information even if no transcript is copied into training. Fit transformations on the training portion, then apply the frozen transformation elsewhere. Keep duplicate and near-duplicate recordings together where they would otherwise cross the boundary.

Decide the comparison and uncertainty plan before seeing the final result. Compare systems on matched examples when appropriate. Record missing data, exclusions and failed cases. Repeatedly adjusting a system after inspecting its test results turns that set into development data, even if its filename still says test.
EXAMPLE:: Fictional manifest:
A1: speaker A, session morning, text “open library”
A2: speaker A, session morning, duplicate of A1
B1: speaker B, session evening, text “close library”
C1: speaker C, session home, text “reserve atlas”

Claim: recognise speech from unseen speakers.
Invalid split: train A1,B1; test A2,C1.
Reason: A2 repeats training audio and speaker A.
Candidate split: train A1,A2; validate B1; test C1.
Limit: only one held-out speaker, so weak population evidence.
EXPLANATION:: The candidate removes the obvious cross-set duplication but remains far too small for a broad claim. A clean boundary is necessary, yet not sufficient. Representative sampling and a defensible uncertainty analysis are separate requirements.
PITFALL:: Calling a set held out does not protect it if its scores repeatedly guide development. File naming and procedural separation are different things.
EXERCISE:: Create a six-row fictional manifest with three speakers and two sessions per speaker. Assign each whole speaker to train, validation or test. Mark one intentional duplicate and keep it in its source group. Write the target claim, split unit and two limits. Do this on paper or in a local text file only.
SOLUTION:: A valid toy design assigns A's sessions to training, B's to validation and C's to test. The duplicate stays beside its original. The claim concerns unseen speakers under the sampled conditions. Limits include tiny speaker counts and inadequate language, accent or device coverage. The table demonstrates split logic, not measured performance.
CHALLENGE:: A team reports improvement after selecting the best of 30 thresholds on its test set. Draft a corrected study plan, including what happens to that old test set, and explain why the published number cannot simply be relabelled independent evidence.
CHALLENGE_SOLUTION:: Treat the inspected set as development material. Freeze the threshold-selection procedure, obtain an appropriate untouched comparison set with permissions, predefine metrics and exclusions, and report uncertainty and selection history. The old number reflects test-informed selection; a different label cannot undo that dependence. No new run is required to identify this limitation.
QUESTION:: Which split best matches a claim about unseen speakers?
CORRECT:: Keep every recording from each speaker within one partition, then assess whether the held-out speakers represent the target population.
WRONG1:: Randomly split audio frames from the same recordings across all partitions.
WRONG2:: Choose whichever split produces the highest reported score.
FEEDBACK:: Separation must match the intended novelty. Preventing speaker leakage still leaves questions of sampling, uncertainty and external validity.

ID:: V11
BRIDGE:: V06 supplies units and powers. Frequency means repetitions per second. You may inspect the supplied numbers visually; no listening experiment, loud playback or microphone recording is needed.
CONCEPT:: Sound travels through air or another material as changes in pressure. A microphone turns those local pressure changes into an electrical signal; a digital system then records samples of that signal. For a repeating wave, frequency describes how often it repeats, amplitude describes its size, and phase describes where its cycle starts.
MECHANISM:: A sinusoid can be written \(x(t)=A\sin(2\pi ft+\phi)\). Here \(A\) is amplitude, \(f\) is frequency in hertz and \(\phi\) is phase offset in radians. Its period is \(T=1/f\). Real speech combines many changing components rather than one perfectly repeating sine wave.
TEACHING:: Maths bridge: a full turn around a circle is \(2\pi\) radians. Sine and cosine connect an angle to coordinates on a unit circle; their values range from -1 to 1. Increasing the angle continuously produces a repeating pattern. In \(2\pi ft\), frequency in cycles/second times time in seconds gives cycles, and multiplying by 2π converts those cycles into radians. This makes the sinusoid formula a timed repeating pattern rather than unexplained notation.

Imagine following one point on a wave over time. Frequency says how quickly a pattern repeats there; amplitude describes the size of the variation. Phase describes where within a repeating cycle the pattern starts relative to a reference. Two signals can share frequency and amplitude but have different phase.

Physical sound-pressure amplitude, a microphone's electrical voltage and a stored digital number are connected through a measurement chain. Changing microphone gain changes stored amplitude without necessarily changing the original source. Comparing levels across devices requires calibration and context.

Pitch and loudness are perceptions, while frequency and amplitude are signal properties. They are related but not identical. A complex periodic signal may contain harmonics at multiples of a fundamental; pitch perception does not reduce to choosing the largest visible spectral peak in every case.
EXAMPLE:: A sinusoidal example uses elapsed time \(t\) in seconds. Let \(\Delta t=0.020\ \mathrm{s}=20\ \mathrm{ms}\) be the observation interval:

\[x(t)=\sin(2\pi\cdot200t),\qquad f=200\ \mathrm{Hz}.\]

\[\begin{aligned}
T&=\frac1f=\frac1{200}\ \mathrm{s}=5\ \mathrm{ms},\\
N_{\text{cycles}}&=f\Delta t=200\times0.020=4.
\end{aligned}\]

The opposite-phase signal \(-x(t)\) has the same frequency and amplitude magnitude. Perfectly aligned addition gives \(x(t)+[-x(t)]=0\). This pure sine contains only the 200 Hz component. A different, complex periodic signal with the same fundamental could also contain harmonics at \(400\), \(600\) and \(800\ \mathrm{Hz}\).
EXPLANATION:: Cancellation in this ideal arithmetic example requires exact alignment and equal opposite signals. Real rooms contain reflections, different paths and changing delays. The example explains phase sensitivity; it does not establish that any noise can be removed by simply reversing recorded samples.
PITFALL:: Frequency is not sample rate. A 200 Hz tone can be represented by many samples per cycle; a 16 kHz sampling rate says how often measurements are stored, not that the sound's pitch is 16 kHz.
EXERCISE:: Calculate periods for 100 Hz, 250 Hz and 1 kHz. Count how many cycles each completes in 40 ms. Draw two cycles of a 250 Hz signal, labelling the time axis in milliseconds. Explain what changes if amplitude halves while frequency stays fixed.
SOLUTION:: Periods are 10 ms, 4 ms and 1 ms. Cycle counts in 40 ms are 4, 10 and 40. Two 250 Hz cycles span 8 ms. Halving amplitude changes vertical scale but not the repetition period; the stored signal level changes without changing this mathematical frequency.
CHALLENGE:: A periodic signal has components at 150, 300 and 450 Hz. A plot shows the largest component at 300 Hz. Explain why concluding “the fundamental must be 300 Hz” is unjustified, and list two measurement-chain details needed before comparing amplitudes with another recording.
CHALLENGE_SOLUTION:: The components are consistent with a 150 Hz fundamental and harmonics. Largest amplitude and lowest repeating frequency are different concepts. Compare microphone calibration/gain and recording distance or preprocessing, among other conditions. A spectral plot alone does not establish perceived pitch or calibrated loudness.
QUESTION:: What is the period of a 250 Hz repeating signal?
CORRECT:: 4 milliseconds.
WRONG1:: 250 seconds.
WRONG2:: 16,000 samples, regardless of sample rate.
FEEDBACK:: Period is reciprocal frequency: 1/250 second = 0.004 second. Sample counts need a sampling rate.

ID:: V12
BRIDGE:: V11 described continuous-time waves and V06 calculated payload sizes. Now connect a physical signal to stored numbers. Keep sample rate, channel count, numeric format and byte order together as one format contract.
CONCEPT:: To store sound digitally, you measure it at selected times: this is sampling. You also round each measurement to an available numeric level: this is quantisation. A codec turns audio into an encoded form and back again, often to save space. A container holds that encoded audio and information about it. These are separate jobs.
MECHANISM:: For a band-limited signal, the sampling theorem requires a sample rate greater than twice the highest retained frequency for ideal reconstruction. Practical acquisition and resampling use anti-alias filtering. Quantisation introduces finite-resolution error. A filename extension alone cannot tell a program how to interpret arbitrary bytes.
TEACHING:: At 16 kHz, consecutive samples are separated by \(1/16{,}000\ \mathrm{s}\), or 62.5 microseconds. That rate has a Nyquist frequency of 8 kHz. This does not mean practical filters retain every component up to exactly 8 kHz without a transition region.

Changing a metadata label does not resample a waveform. If 16,000 samples captured at 16 kHz are played as 8 kHz, playback lasts two seconds rather than one and pitch changes. Proper resampling computes a new sequence while preserving intended duration and the supported bandwidth.

PCM stores sample values directly in a specified integer or floating-point representation. Stereo channels may be interleaved. Compressed formats such as Opus use a different representation; their bytes cannot be treated as raw 16-bit samples. Decoding, channel conversion and resampling are distinct steps that should be documented.

Anti-aliasing keeps the representable band: before reducing the sample rate, attenuate frequencies above the new Nyquist limit, allowing a practical transition band below it. Removing low frequencies instead would not solve aliasing. This corrects a reversed word in the assigned video’s caption explanation. The course’s 16 kHz/16-bit examples are format choices, not requirements for every speech system.

Quantisation example: suppose a toy device permits only levels -1, 0 and 1. Rounding a measured 0.3 to 0 changes it by -0.3; rounding 0.8 to 1 changes it by +0.2. More representable levels can reduce that rounding error under a defined range, but do not fix clipping outside the range. Real 16-bit integer PCM uses many more levels. “Signed” means negative and positive values are representable. “Little-endian” means the least significant byte is stored first; the byte-pair examples below assume that order and signed two’s-complement encoding. Do not apply those interpretations to compressed bytes.
EXAMPLE:: PCM assumptions: mono, signed 16-bit little-endian. Bytes 00 00 represent 0; 01 00 represent 1; FF FF represent −1. These are byte encodings; use the stated sample format to interpret them.

For a frame containing \(N=320\) samples:

\[\begin{aligned}
T_{16\,\mathrm{kHz}}&=\frac{320}{16{,}000}\ \mathrm{s}=20\ \mathrm{ms},\\
T_{8\,\mathrm{kHz}}&=\frac{320}{8{,}000}\ \mathrm{s}=40\ \mathrm{ms}.
\end{aligned}\]

Without appropriate pre-sampling filtering, a \(10\ \mathrm{kHz}\) sinusoid sampled at \(16\ \mathrm{kHz}\) aliases to \(6\ \mathrm{kHz}\).
EXPLANATION:: The byte examples rely on all stated format assumptions. Aliasing makes different continuous-time signals produce indistinguishable sampled patterns. Once that information has been lost during acquisition, simply increasing the sampling-rate label cannot recover it.
PITFALL:: Downsampling by keeping every other sample without filtering can fold unsupported frequencies into the retained band. Upsampling later does not reconstruct the original lost information.
EXERCISE:: For 48 kHz mono PCM, calculate the samples in 10, 20 and 30 ms. Calculate the payload bytes for each at 16 bits/sample. Then explain how the answer changes for stereo. Finally describe the steps required to turn a compressed stereo recording into mono 16 kHz PCM without merely relabelling it.
SOLUTION:: The counts are 480, 960 and 1,440 samples per channel; mono payloads are 960, 1,920 and 2,880 bytes. Stereo doubles them. Decode the codec, use a documented channel-mixing policy, apply suitable filtered resampling, then encode the requested PCM representation and metadata. Confirm duration and format.
CHALLENGE:: A one-second, 48 kHz file is labelled 16 kHz without changing its 48,000 samples. Predict playback duration. Contrast this with proper 48-to-16 kHz resampling, stating output count, duration and the reason for low-pass filtering.
CHALLENGE_SOLUTION:: Relabelled playback lasts three seconds. Proper resampling produces approximately 16,000 samples for one second, subject to a documented boundary convention. Low-pass filtering removes content that cannot be represented below the new Nyquist frequency, preventing it from aliasing into the retained band.

CORRECT:: No. Proper resampling computes a new sample sequence with appropriate filtering.
WRONG1:: Yes. The same stored samples automatically gain the missing information.
WRONG2:: Yes, provided the filename ends in .wav.

ID:: V13
BRIDGE:: V11 introduced waves. Now learn the human mechanisms that create speech. The IPA is a notation system, not a requirement that everyone speak with one accent. Use demonstrations and diagrams; do not perform an examination on anyone.
CONCEPT:: Phonetics is the study of speech sounds: how we make them, how they behave as sound and how we hear them. A letter on a page is not the same thing as a sound. A sound you hear is also not automatically the same as a sound category in a particular language. Keeping these distinctions clear helps you understand pronunciation and variation.
MECHANISM:: Airflow, vocal-fold activity and movements of the tongue, lips and other structures shape speech. Consonants can be described by place, manner and voicing. Vowels are commonly described by tongue height, frontness and lip rounding. The International Phonetic Alphabet provides symbols for describing sounds across languages.
TEACHING:: Use three questions for a consonant. Place: where is airflow narrowed? Bilabial means using both lips; alveolar means the tongue approaches the ridge behind the upper teeth. Manner: how does air pass? A stop briefly blocks and releases it; a fricative creates a narrow turbulent passage; a nasal lets airflow pass through the nose. Voicing describes vocal-fold vibration patterns, with language/context-specific timing. Slashes such as /p/ here indicate broad sound-category notation, not spelling. These definitions let you read the chart without assuming anatomical terminology.

Start with one contrast. In many English varieties, /p/ and /b/ share a bilabial place and stop manner but differ in voicing-related production patterns. Real acoustic realisations depend on context and language; a category label does not imply that every token has identical timing.

Orthography is an imperfect sound guide. The letters in a word do not map one-for-one to phonemes. A phone is a particular speech sound; a phoneme is a contrastive category within a language. Pronunciation dictionaries encode a chosen language and convention, so they need dialect and vocabulary context.

Speech movements overlap. Coarticulation means neighbouring sounds influence one another, so isolated dictionary sounds do not simply concatenate into natural connected speech. An accent difference is not automatically an error, and a system's difficulty with a speaker does not establish a speech disorder.

An affricate begins with a stop-like closure and releases into frication, as in English /tʃ/ at the start of “chair”. A tap uses one very brief contact; /ɾ/ is a tongue-tip tap in many Spanish varieties. These are additional manner categories on the IPA chart, rather than variants of every stop or fricative.

A white cell without a printed IPA symbol does not prove no language uses that sound; diacritics can represent additional combinations. In common English descriptions, /ʃ,ʒ/ are postalveolar, /j/ is palatal, /l/ is lateral and /ɹ/ is an approximant with varying realisations, not simply another lateral. The chart and language-specific descriptions are more precise than treating every “liquid” as the same manner. Broad symbols omit details that a narrower transcription can add.
EXAMPLE:: Compare sound descriptions, not spelling:
/p/: bilabial stop, conventionally voiceless.
/b/: bilabial stop, conventionally voiced.
/m/: bilabial nasal, conventionally voiced.

The English spelling “ship” has four letters but commonly
three phonemes: /ʃ/, /ɪ/, /p/ in a suitable transcription.
The symbols describe a pronunciation convention, not all accents.
EXPLANATION:: The three consonants show how one articulatory feature can change while others remain similar. The spelling example shows why a TTS system needs pronunciation handling instead of a rule that speaks each letter independently. A broad transcription intentionally omits finer detail.
PITFALL:: Do not treat an IPA transcription as a universal spelling correction or a clinical judgement. Category systems and broad transcriptions simplify a variable physical process.
EXERCISE:: Use the assigned consonant and vowel demonstrations and IPA chart to compare /t/, /d/, /s/ and /n/. Make columns for place, manner and conventional voicing. CHALLENGE_SOLUTION:: Letter/sound counts differ; spelling is context-dependent; connected speech includes prosody and coarticulation. CORRECT:: Written letters and speech sounds do not have a universal one-to-one correspondence.
WRONG1:: Every language uses English spelling-to-sound rules.
WRONG2:: A system's transcription error proves that the speaker has a disorder.

ID:: V14
BRIDGE:: V11 introduced periodic signals and V13 described speech production. Resonance means a system responds more strongly near some frequencies than others. Here we model the vocal tract roughly as a changing acoustic tube that emphasises some parts of the source sound. Its resonances are not generally harmonics of the vocal-fold repetition rate. This engineering model simplifies the physical process; it is useful for reasoning about speech, not for diagnosing a person’s voice or anatomy.
CONCEPT:: The source–filter model gives you two parts to think about: what creates a sound and how the vocal tract changes it. For many voiced sounds, vocal-fold vibration provides the source. The shape of the throat and mouth filters it. This helps explain why changing pitch and changing a vowel are different operations, even though they interact.
MECHANISM:: For many voiced sounds, approximately periodic vocal-fold excitation supplies harmonics. The vocal tract shapes their amplitudes through resonances. In this simplified picture, the tract strengthens some source harmonics and weakens others. V15–V16 develop the mathematical description of this filtering. Unvoiced and mixed sounds need different or additional excitation descriptions.
TEACHING:: Think of two controls. Changing the source repetition rate changes the fundamental frequency and harmonic spacing. Changing the filtering shape changes which frequency regions are emphasised. This separation is approximate: real speech production is dynamic, and interactions can violate a simple independent linear model.

Formants describe resonant regions of the vocal-tract filtering effect, not individual harmonics. A spectral peak near a resonance can reflect both the filter envelope and available source harmonics. Short analysis windows, noise and high fundamental frequencies can complicate estimation.

For a vowel, the first two formants often help describe its acoustic quality, but their values vary with speaker, language and context. A small table of frequencies is not enough to classify every vowel or infer personal characteristics. Later TTS systems learn richer representations, while this model remains a helpful conceptual bridge.
EXAMPLE:: Keep the simplified source and filter separate:

\[F_0=100\ \mathrm{Hz},\qquad f_k=kF_0\quad(k=1,2,3,\ldots).\]

The initial harmonic grid is \(100,200,300,\ldots\ \mathrm{Hz}\). Assume filter resonances near \(500\) and \(1{,}500\ \mathrm{Hz}\).

If the source changes to \(F_0=200\ \mathrm{Hz}\) while that simplified filter stays fixed, the grid becomes \(200,400,600,\ldots\ \mathrm{Hz}\). The filter's resonant regions remain near the same two values; harmonics and formants are different objects.
EXPLANATION:: Doubling F0 changes the harmonic grid; it does not, in this simplified model, double the formant frequencies. The source may sample a filter envelope sparsely, so one cannot read a resonance by blindly selecting the tallest harmonic.
PITFALL:: Pitch shifting and changing vowel quality are not the same transformation. A model that separates them approximately still has limitations, especially for rapid, mixed or irregular phonation.
EXERCISE:: Draw a harmonic grid for F0 values 100 and 250 Hz up to 2 kHz. Overlay a broad resonant region at 700 Hz. Explain why the strongest nearby harmonic may appear at different locations. Then list two reasons real speech would depart from this stationary diagram.
SOLUTION:: At 100 Hz the nearby harmonics include 600,700,800; at 250 Hz they include 500,750,1000. A broad envelope weights whichever harmonics exist. Articulator movement changes the filter over time, and excitation may be irregular or mixed with turbulence. The diagram cannot fix either behaviour.
CHALLENGE:: A colleague doubles all frequencies in a recording and claims only pitch changed. Explain the expected effect on resonances and duration under simple sample-rate relabelling, and describe what evidence a pitch-only claim would need.
CHALLENGE_SOLUTION:: Simple faster playback raises both harmonic and resonant frequencies and shortens duration. A pitch-only transformation needs a different method and a stated preservation target. Compare duration and spectral-envelope behaviour on appropriate permitted material; a pleasant listening impression alone does not establish preservation.
QUESTION:: In the simplified source–filter model, what primarily sets harmonic spacing?
CORRECT:: The repetition rate of the voiced excitation source.
WRONG1:: The filename of the recording.
WRONG2:: The first formant always equals the fundamental frequency.
FEEDBACK:: Source repetition and filter resonances are distinct model components. Their observed interaction still depends on analysis and real-speech limitations.

ID:: V15
BRIDGE:: V07 introduced vectors, V12 digital samples and V14 harmonics. A Fourier transform expresses a finite signal using sinusoidal components. Work with the tiny supplied sequence before studying larger spectrograms.
CONCEPT:: A waveform shows how a signal changes over time. A spectrum shows the frequency components in one chosen interval. A spectrogram places spectra from many short intervals next to each other. You can then see how the frequency pattern changes as someone speaks. Each view answers a different question about the same recording.
MECHANISM:: A discrete Fourier transform (DFT) maps N samples to N complex coefficients. For sample rate fs, frequency-bin spacing is fs/N. A short-time Fourier transform (STFT) repeats this calculation on overlapping, windowed frames. Complex coefficients carry magnitude and phase; a magnitude spectrogram omits phase information.
TEACHING:: A complex number has real and imaginary parts. In this setting they encode the weights of sine/cosine components, allowing both amplitude and phase to be represented. You can reason about a magnitude display without doing complex arithmetic immediately, but reconstructing a waveform generally needs phase as well.

Window length creates a trade-off. A longer window provides finer frequency-bin spacing but mixes changes over a longer time interval. A shorter window localises events in time while spreading frequency information. Hop length controls how far the analysis advances between frames; it is not the same as window length.

Windowing reduces abrupt edge discontinuities but changes how energy spreads across bins. Zero-padding creates a denser sampled display of a spectrum; it does not create the information of a longer observed signal. Always label sample rate, window, hop, frequency scale and magnitude scale when sharing a spectrogram.

Make the transform concrete with four samples \(\mathbf{x}=[1,0,-1,0]\). For this example use a rectangular window, N = 4 and the unnormalised forward DFT. At bin k, multiply each sample by \(\cos(2\pi kn/N)-i\sin(2\pi kn/N)\), then sum over n = 0,1,2,3. The symbol i satisfies \(i^2=-1\); \(a+bi\) stores two real components. Its magnitude is \(\sqrt{a^2+b^2}\). You do not need to manipulate an unexplained exponential to do this four-point case.

At k = 0 all cosine factors are one and sine factors zero, so \(X[0]=1+0-1+0=0\). At k = 1, cosine factors \([1,0,-1,0]\) and sine factors \([0,1,0,-1]\) give real part 2 and imaginary part 0. At k = 2 the alternating cosine pattern gives zero. Bin 3 gives 2 again. Thus \(\mathbf{X}=[0,2,0,2]\). At fs = 8 Hz, the bin frequencies are 0,2,4,6 Hz; for a real input the final bin represents the matching negative-frequency component. This is a tiny synthetic illustration, not a recording.

Change only the input to \([0,1,0,-1]\). The coefficients become \([0,-2i,0,2i]\): the magnitudes stay \([0,2,0,2]\) but the phase changes. That is why a magnitude plot alone loses information. In speech, repeat an appropriately windowed transform across overlapping frames to obtain an STFT. Do not confuse bin spacing fs/N with the ability to resolve arbitrary nearby tones; window duration, shape and leakage matter.

The unnormalised forward transform used above can be written compactly as:

\[X[k]=\sum_{n=0}^{N-1}x[n]\left[\cos\!\left(\frac{2\pi kn}{N}\right)-i\sin\!\left(\frac{2\pi kn}{N}\right)\right].\]

Here \(n\) indexes time samples and \(k\) indexes frequency bins. This is the same sine/cosine calculation already worked above, not a different transform.
EXAMPLE:: Let \(f_s=16{,}000\ \mathrm{Hz}\), frame length \(N=400\), and hop length \(H=160\).

\[\begin{aligned}
T_{\text{window}}&=\frac{N}{f_s}=25\ \mathrm{ms},\\
\Delta f&=\frac{f_s}{N}=40\ \mathrm{Hz},\\
T_{\text{hop}}&=\frac{H}{f_s}=10\ \mathrm{ms}.
\end{aligned}\]

For \(N=800\) at the same sample rate:

\[T_{\text{window}}=50\ \mathrm{ms},\qquad\Delta f=20\ \mathrm{Hz}.\]

Zero-padding 400 observed samples to length 800 does not observe 50 ms of sound. It changes the display grid, not the duration of the evidence.
EXPLANATION:: The 800-sample observed window can resolve finer frequency structure under appropriate conditions because it contains more time information. Padding a shorter window changes the display grid rather than the amount of observed evidence. A 10 ms hop does not make a 25 ms window instantaneous.
PITFALL:: A spectrogram is an analysis choice, not a photograph of uniquely determined frequency truth. Different windows and scales can make the same recording look different.
EXERCISE:: Calculate duration and bin spacing for N = 256 and N = 512 at 16 kHz. Calculate the time between frame starts for a 128-sample hop. Explain which setting you would inspect for a rapid consonant transition and what frequency-detail trade-off you would report.

Before the plot critique, reproduce the four-point transform for \([1,0,-1,0]\) and then \([0,1,0,-1]\) using the supplied sine/cosine factors. Report real and imaginary parts and explain why equal magnitudes do not mean identical signals.
SOLUTION:: The windows are 16 and 32 ms, with bin spacings 62.5 and 31.25 Hz. The hop is 8 ms. The shorter window may better localise a rapid transition, while offering coarser frequency discrimination. State that the suitability depends on the particular analysis question, window shape and signal.

The respective transforms are \([0,2,0,2]\) and \([0,-2i,0,2i]\) under the stated forward convention. Their magnitudes agree, but their samples and phases differ. Reversing the transform sign convention changes the imaginary signs; it must be stated consistently.
CHALLENGE:: Using the forward convention and sine/cosine factors in Learn, compute the four-point DFT of the new input \([1,1,-1,-1]\). Show real and imaginary parts and the nonzero magnitudes. Then a report compares two spectrograms without sample rate, window length or dB reference and claims noise removal: write a corrected reporting checklist and explain why the images alone do not establish improved speech quality.
CHALLENGE_SOLUTION:: The new transform is \([0,2-2i,0,2+2i]\). Bin zero sums to zero; bin two is \(1-1-1+1=0\). Bin one is \(1-i+1-i=2-2i\), and bin three is its conjugate \(2+2i\). The two nonzero magnitudes are \(\sqrt{2^2+2^2}=2\sqrt2\). Request sample rate, frame/hop lengths, window function, transform size, magnitude/power convention, scale/reference and identical display limits. Require a comparison using the same input and meaningful quality evidence. A cleaner-looking display can still conceal speech distortion.
QUESTION:: What does zero-padding a short frame provide?
CORRECT:: A denser frequency display grid, without adding newly observed signal information.
WRONG1:: The same information as recording a genuinely longer interval.
WRONG2:: Guaranteed recovery of every missing speech component.
FEEDBACK:: Observation duration and transform size are related but distinct. More plotted bins do not imply more independent information.

ID:: V16
BRIDGE:: V15 supplies spectra and windows. Here a filter transforms a signal, while a feature summarises selected aspects of it. You need addition, multiplication and careful indexing; work through the short sequence before using an audio library.
CONCEPT:: A filter changes a signal by combining nearby values according to a rule. Convolution is one way to describe that calculation. Feature extraction then turns audio into measurements that a model can use, such as energy in frequency bands. Ask what each representation keeps and what it loses: a useful summary is still different from the original waveform.
MECHANISM:: A finite impulse response filter multiplies nearby samples by chosen weights and adds the results. A mel filter bank groups spectral energy into overlapping frequency bands. Further steps take logarithms and, for MFCCs, apply a discrete cosine transform. These operations create different summaries. Record their settings; neither mel features nor MFCCs are another name for the waveform.
TEACHING:: Consider a two-sample moving average. Each output combines half the current sample and half the previous sample, with an explicit boundary convention. It smooths rapid changes but also changes the signal. Whether that is useful depends on the task; smoothing is not a universal improvement.

For speech features, start with framed spectra. Choose a magnitude or power convention, then a band bank and a stable logarithm rule. A log needs positive input, so numerical implementations use a documented floor or equivalent stabilisation. Different choices can produce incompatible feature values from the same audio.

The mel scale provides a frequency-warping convention used widely in speech systems. MFCCs additionally transform log-band energies and often retain selected coefficients. They can be helpful for some models but may remove detail needed for reconstruction or newer systems. Do not add familiar preprocessing to a pretrained model unless it matches that model's expected input contract.

Follow one feature frame all the way through. Suppose three non-negative spectral-power bins are [1,4,1]. A deliberately tiny two-band bank with rows [0.5,0.5,0] and [0,0.5,0.5] produces energies [2.5,2.5] by matrix multiplication. Taking natural logarithms gives approximately \([0.9163,0.9163]\). Real mel banks use documented frequency locations and usually many more bands; these toy weights only expose the operations.

MFCCs apply a discrete cosine transform to the log-band vector. Under an unnormalised two-point DCT-II, coefficient k is the sum of log_energy[m] × \(\cos\!\left(\frac{\pi k(m+0.5)}{2}\right)\) over m = 0,1. Here k=0 gives 1.8326 and k=1 gives zero because the cosine weights cancel. Other normalisations rescale these numbers. Keeping only selected coefficients discards information. A mel spectrogram and an MFCC array are therefore different interfaces even if their dimensions accidentally match.

For the moving-average exercise, also try x = [0,2,2,2]. The first four causal outputs are [0,1,2,2], and full convolution adds a final 1. Truncation hides a nonzero tail in this version. Boundary handling is part of a filter contract, not an incidental plotting choice.
EXAMPLE:: Use \(\mathbf{x}=[2,4,0,2]\), \(\mathbf{h}=[\tfrac12,\tfrac12]\), zero initial history \(x[-1]=0\), and four causal outputs:

\[y[n]=\tfrac12x[n]+\tfrac12x[n-1].\]

\[\begin{aligned}
y[0]&=\tfrac12(2)+\tfrac12(0)=1,\\
y[1]&=\tfrac12(4)+\tfrac12(2)=3,\\
y[2]&=\tfrac12(0)+\tfrac12(4)=2,\\
y[3]&=\tfrac12(2)+\tfrac12(0)=1.
\end{aligned}\]

This convention truncates the filter tail. Full convolution would include the final sample \(y[4]=1\).
EXPLANATION:: A full convolution would include one additional tail output, also equal to one here. Both outputs can be legitimate under different conventions, but they answer different questions. Explicit boundary and alignment rules prevent a silent one-frame timing error later in a voice pipeline.
PITFALL:: Feature extraction is part of the model contract. Matching the number of features does not establish compatibility if sample rate, frame alignment, normalisation or power conventions differ.
EXERCISE:: Apply the same causal filter to [0, 2, 2, 0] using zero initial history. Write four outputs and the full-convolution tail. Then list six parameters you would record when exporting log-mel features for another researcher.

Repeat with [0,2,2,2] and show the nonzero tail. Then compute the two-band energies, logs and two DCT coefficients in the toy feature frame from Step by step, naming its normalisation.

Record sample rate, frame length, hop, window, frequency/mel-band configuration and magnitude/power plus log-floor convention; also document normalisation, transform size and boundary handling where relevant. A feature array alone is insufficient documentation.

For [0,2,2,2], truncated output is [0,1,2,2] and the extra full-convolution sample is 1. Toy band energies are [2.5,2.5], natural logs approximately \([0.9163,0.9163]\), and the stated unnormalised DCT-II gives \([1.8326,0]\).
CHALLENGE:: Two systems both export 80 features per frame, but one uses 16 kHz audio with 10 ms hops and the other 48 kHz with 20 ms hops. Explain why their arrays cannot simply be exchanged, and draft a compatibility check before any model is loaded.
CHALLENGE_SOLUTION:: Their timing, bandwidth and potentially band definitions differ. Reject or deliberately transform incompatible data with documented loss; do not assume equal feature count establishes equal meaning.
QUESTION:: Why document a convolution boundary convention?
CORRECT:: It determines output length, edge values and timing alignment.
WRONG1:: Boundaries never affect finite signals.
WRONG2:: It guarantees that every filter improves speech intelligibility.

ID:: V17
BRIDGE:: V07 provides vector calculations, V08 gradients, V09 probability and V10 data boundaries. Combine them into a small model whose arithmetic you can inspect. The supplied exercise uses fictional numbers and no training service.
CONCEPT:: Machine learning uses examples to choose a model’s parameters. If you predict a number, such as a duration, the task is regression. If you choose a category, such as speech or silence, the task is classification. What the model learns depends on the inputs, target answers and loss you choose, and on which data you keep for testing.
MECHANISM:: A linear regression model predicts \(\widehat y=wx+b\). A loss measures disagreement with supplied targets; optimisation adjusts \(w\) and \(b\) to reduce training loss. Logistic classification converts a score into a value between zero and one, but that value is not automatically a calibrated probability in a new population.
TEACHING:: Separate four objects: the input, target, prediction and loss. A target is an annotation that may contain error; a prediction is a model output; loss is an accounting rule. None is the same as the user's real-world objective. Predicting a convenient label may fail to improve a conversation.

Compare with a simple baseline. If a sophisticated model barely improves on predicting the training mean, ask whether its complexity is useful. Fit all parameters and preprocessing within the training boundary. Use validation for choices and preserve a genuine held-out comparison for the final claim.

Overfitting means a model captures training-specific detail that does not transfer adequately. Regularisation expresses preferences such as smaller weights, but does not repair leakage or an unrepresentative dataset. Consider the complete data process before attributing every failure to architecture.

Classification needs more than a threshold label. In a binary logistic model, \(z=\mathbf{w}\cdot\mathbf{x}+b\) is converted to \(p=\frac1{1+\exp(-z)}\). At z=0, p=0.5; at \(z=\ln3\), p=0.75. A threshold converts this score to a decision, while calibration asks whether similar predicted probabilities match observed frequencies in appropriate independent data. A threshold and a probability are different objects.

For target y=1, binary cross-entropy is \(-\ln p\); for y=0 it is \(-\ln(1-p)\). A correct-class probability 0.75 gives loss about 0.288, whereas 0.25 gives about 1.386. The loss penalises confident errors strongly, but minimising it still does not choose the right product trade-off. With 98 silent clips and two speech clips, always predicting silence misses both speech clips despite 98% accuracy. Write a confusion table and define costs before choosing an endpointing threshold.

For the tree videos, a split asks a question about an input feature; a leaf holds a class decision or regression value. Entropy measures class uncertainty: \(H=-\sum_c p_c\log_2 p_c\), with a zero-proportion term contributing zero. Compare a proposed split using weighted child entropy \(\sum_j(n_j/n)H_j\); a tiny pure child must not count as much as a large child. Information gain subtracts this from parent entropy. Choosing splits on training data is a learning procedure, distinct from the resulting tree and from checking transfer to held-out speakers.
EXAMPLE:: Fictional training pairs are \((0,1),(1,3),(2,5)\). For a prediction rule \(\widehat y\), define:

\[\mathrm{MSE}=\frac1n\sum_{i=1}^{n}(\widehat y_i-y_i)^2.\]

\[\begin{aligned}
\text{Model A: }\widehat y&=2x+1, & \mathrm{MSE}_A&=0,\\
\text{Baseline: }\widehat y&=\overline y_{\text{train}}=3,
& \mathrm{MSE}_{\text{base}}&=\frac{4+0+4}{3}=\frac83.
\end{aligned}\]

On the separate supplied pair \((3,8)\), Model A predicts \(7\), with squared error \((7-8)^2=1\). This one pair is not a generalisation study.
EXPLANATION:: Zero loss on three training pairs does not imply zero loss everywhere. The new pair exposes the distinction immediately. This calculation compares stated predictions; it does not establish that either model is appropriate for speech, nor require fitting or running a provider model.
PITFALL:: A numeric score becomes meaningful only through its definition and validation. A classifier output of 0.95 is not a universal 95% guarantee of correctness, especially after distribution shift.
EXERCISE:: For the same training pairs, calculate predictions and mean squared error for y_hat = x + 1. Compare all three candidate rules. Write one validation question about transfer and one about annotation quality. Identify which quantities were chosen before seeing the new pair.
SOLUTION:: Predictions are [1,2,3], squared errors [0,1,4], and mean squared error 5/3. This is between A's zero and the constant baseline's 8/3 on training data. Ask whether new inputs follow comparable relationships and whether targets are trustworthy. A transfer claim requires more than these hand-picked examples. The training pairs, candidate formulas and training-mean baseline were fixed before the new pair (3,8) was inspected. Choosing or tuning a candidate after seeing that pair would use it for model selection rather than untouched testing.
CHALLENGE:: A classifier is 98% accurate where 98% of examples are silence. Explain the trivial baseline, the missing error information and why accuracy alone cannot justify using it to decide when a user has stopped speaking.
CHALLENGE_SOLUTION:: Always predicting silence achieves 98% on that mix. Request speech/silence counts, false speech rejections, false activations, timing and subgroup information. A turn-ending decision has asymmetric conversational costs and temporal requirements. A high aggregate accuracy can coexist with rejecting every speech example.
QUESTION:: What does zero training loss establish?
CORRECT:: Agreement with the chosen training objective on those examples, subject to its definitions.
WRONG1:: Guaranteed correct behaviour on every future speaker.
WRONG2:: Proof that every training label is correct.
FEEDBACK:: Training fit, label quality and generalisation are separate claims requiring different evidence.

ID:: V18
BRIDGE:: V17 supplied losses and learned parameters. V08's chain rule now connects several transformations. Use the supplied arithmetic first; the linked lectures and book develop the full derivation before you attempt larger networks independently.
CONCEPT:: A neural network passes values through a series of learned calculations and nonlinear functions. Each layer builds on the previous layer’s output. Backpropagation works backwards through those calculations to find how each parameter affects the loss. You still have to choose a useful objective and suitable data; calculating gradients cannot make those choices for you.
MECHANISM:: A simple neuron computes \(z=wx+b\), then applies \(h=\max(0,z)\), called ReLU. A later layer uses \(h\) to predict an output. The chain rule propagates derivatives backward through the saved computation. A batch groups examples while retaining their intended axes and boundaries.
TEACHING:: Trace the forward pass before the backward pass. Save each intermediate value because it determines the relevant derivative. ReLU's derivative is one for positive input and zero for negative input; exactly zero needs an implementation convention. Never infer gradients from variable names without examining the actual computation.

For a loss built from squared error, the output derivative reflects the difference from the target. Multiplying by successive local derivatives tells us how an upstream weight influenced that error. A negative gradient means increasing the parameter locally reduces the loss under a sufficiently small step.

Training procedure matters. Parameter initialisation, scale, optimiser settings, batching, masking and preprocessing can alter learning. A larger network has more capacity, not automatic immunity to bad labels, speaker leakage or a mismatched deployment setting. Keep the scientific boundaries from V10 even when a library handles the arithmetic.

When a variable influences the loss through several branches, add every branch contribution. If \(u=x^2\), \(v=3x\) and \(L=u+v\), then \(dL/dx=2x+3\), not just \(2x\). At \(x=2\), the derivative is seven. More generally, for intermediate variables \(z_i(x)\),

\[\frac{dL}{dx}=\sum_i\frac{\partial L}{\partial z_i}\frac{dz_i}{dx}.\]

Products propagate through a path; sums combine paths. Save the forward-pass values so each local derivative is evaluated at the same parameter setting. The lecture's small-perturbation equations describe first-order behaviour, not exact changes for every finite step.

In the optional matrix notation, \(\mathbb{R}\) denotes real numbers, \(\mathbb{R}^m\) vectors with m real entries, and a superscript transpose swaps rows and columns. For the optional matrix extension, fix a convention before copying equations. Use column vectors and one affine layer \(z=Wh+b\), with \(h\in\mathbb R^m\), \(z,b\in\mathbb R^n\) and \(W\in\mathbb R^{n\times m}\). If \(g_z=\nabla_zL\) is a column vector, then

\[g_h=W^\top g_z,\qquad \nabla_WL=g_zh^\top,\qquad \nabla_bL=g_z.\]

The matrix gradient has shape \(n\times m\), matching the parameter to update. With \(h=(2,3)^\top\) and \(g_z=(4,5)^\top\), the weight gradient is

\[\nabla_WL=\begin{bmatrix}8&12\\10&15\end{bmatrix}.\]

Each entry is the corresponding output sensitivity multiplied by the input on that connection. A bias is added with local derivative one. The CMU matrix lecture writes row sensitivities; its row derivative propagates by right-multiplying W, the transpose-equivalent of the column formula above. Do not mix those conventions or assume that matching matrix dimensions proves the derivative correct. These supplied calculations require no network execution.
EXAMPLE:: Given \(x=2,w=1,b=0,v=3,y=4\), use \(h=\operatorname{ReLU}(z)\):

\[\begin{aligned}
z&=wx+b=2,&h&=2,\\
\widehat y&=vh=6,&L&=(\widehat y-y)^2=4.
\end{aligned}\]

All gradients refer to those original parameter values:

\[\begin{aligned}
\frac{\partial L}{\partial\widehat y}&=2(6-4)=4,\\
\frac{\partial L}{\partial v}&=4h=8,\\
\frac{\partial L}{\partial w}&=4v\cdot1\cdot x=24,\\
\frac{\partial L}{\partial b}&=4v\cdot1=12.
\end{aligned}\]
EXPLANATION:: When updating several parameters, compute their gradients from one consistent forward pass before applying the step. Updating v early and then using its new value to calculate w's old-pass gradient would mix two different computations.
PITFALL:: A gradient is not an explanation that a model's decision is clinically, socially or linguistically correct. It measures local mathematical sensitivity of a specific objective.
EXERCISE:: Repeat the forward pass with w=-1, keeping the other supplied values fixed. Calculate prediction, loss and the gradients for w, b and v away from ReLU's zero point. Explain why this single example can leave the hidden unit inactive.
SOLUTION:: z=-2, h=0, prediction=0 and loss=16. The ReLU derivative is zero, so gradients for w and b are zero; dL/dv also equals zero because h=0. This path supplies no weight update from that example. Other inputs or architecture choices may behave differently.

CHALLENGE_SOLUTION:: New parameters are w=0.76, b=-0.12 and v=2.92. z=1.4, prediction=4.088 and loss=0.007744. This one step reduces this one example's loss. It does not establish generalisation, convergence for arbitrary settings or suitable real-world behaviour.
QUESTION:: Why calculate all gradients before applying a simultaneous update?
CORRECT:: They must refer to the same parameter state and forward computation.
WRONG1:: It guarantees the network cannot overfit.
WRONG2:: It makes the training labels correct automatically.
FEEDBACK:: Consistent gradients establish the intended mathematical update. They do not solve data quality or generalisation problems.

ID:: V19
BRIDGE:: V18 introduced composed layers, V16 audio features and V07 tensor axes. A sequence is an ordered collection whose positions matter. The assigned sequence and attention lectures provide the mathematical depth beyond this small attention calculation.
CONCEPT:: Speech arrives in a sequence, so the meaning of one part can depend on other parts. Attention lets a model combine information from selected positions in that sequence. A transformer uses attention together with feed-forward layers and other components. To understand it, follow which positions can contribute information and how their contributions are weighted.
MECHANISM:: Scaled dot-product attention forms scores \(QK^{\mathsf T}/\sqrt{d_k}\), applies a mask where required, converts scores to weights with softmax, and uses those weights to combine \(V\) values. Queries, keys and values are learned representations. A causal mask prevents access to later positions; padding masks prevent fabricated padding from acting like real data.
TEACHING:: A token is one discrete unit in a model’s sequence vocabulary: for text it might be a character, a word piece or a word; an audio codec can use integer codebook indices. A token is not automatically a word or a fixed-duration acoustic frame. An embedding turns an index or input segment into a learned vector of numbers, so later layers can work with it. A lookup table may give one vector per vocabulary item; contextual layers then change the representation with surrounding information. A speaker embedding instead summarises an audio segment into a fixed-length vector for a speaker-related task. Similar vectors are model-dependent evidence, not proof of identity.

Think of a query as the information a position is looking for, a key as an address-like matching representation and a value as information to combine. This is an intuition, not a literal database lookup: attention generally mixes several values rather than returning one discrete record.

Softmax turns finite scores into positive weights summing to one. Equal scores give equal weights. Adding a constant to every score leaves the distribution unchanged. The scaling factor helps control score size as representation dimension grows; numerical implementations still need stable arithmetic.

Order and availability are separate concerns. Position information distinguishes otherwise similar tokens at different sequence locations. A causal mask enforces a temporal information boundary. An offline encoder may use future audio, whereas a streaming system cannot access samples that have not arrived. An architecture claim must state this difference.

Work an unequal-score example using V07's dot product. Let q=[1,0], k1=[0,1], k2=[\(\ln3\),0], with d_k=2. Raw dot products are 0 and \(\ln3\). Scaled scores divide by \(\sqrt2\), giving 0 and about 0.7768. Softmax exponentiates then normalises: [1,2.1746]/3.1746 ≈ \([0.3150,0.6850]\). For values [2,6], the weighted output is about 4.740. Without the scaling the weights would be \([0.25,0.75]\), so omitting it changes the calculation.

With T query positions and feature width d_k, Q and K have shapes \((T,d_k)\); \(QK^{\mathsf T}\) is \((T,T)\). Each row scores the available key positions for one query. Values may have width d_v, giving output shape \((T,d_v)\). Mask forbidden logits before softmax. A row with no allowed keys needs an explicit handling policy; softmax of an all-masked row is not a meaningful distribution. Residual connections add a transformed representation to its input when shapes match; normalisation and feed-forward layers are further transformer components, not synonyms for attention.

Scaled dot-product attention puts those operations together:

\[\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}+M\right)V.\]

The mask \(M\) has zero at allowed locations and \(-\infty\) at forbidden locations, with at least one permitted key per processed row. Softmax acts across each query's key scores.

The video draws attention weights with each query in a column; our equations put queries in rows. Keep the layout consistent: for \(Q\in\mathbb{R}^{T_q\times d_k}\), \(K\in\mathbb{R}^{T_k\times d_k}\) and \(V\in\mathbb{R}^{T_k\times d_v}\), scores have shape \(T_q\times T_k\) and each query row is normalised across keys. For cross-attention, queries can come from the decoder while keys and values come from encoder outputs. Cross-attention may also need padding or availability masks. The terms value-down/value-up in the video are explanatory names; common notation uses per-head value projections and a combined output projection. Learned heads need not correspond to one clean linguistic rule.

The optional CMU lectures use older recurrent encoder–decoder models to introduce attention before removing recurrence. Learned compatibility parameters produce new attention coefficients for each input and decoder step; the normalised coefficients are not fixed per-position parameters. In the Transformer, query and key projections are distinct. A query–query verbal slip in the lecture is not the equation to implement. Multiple heads are concatenated and projected; distinct linguistic roles are not guaranteed.

Teacher-forced autoregressive training uses shifted known target tokens and a causal mask, so a prediction cannot inspect the target it is meant to predict. Parallel training does not make ordinary token-by-token generation parallel. Position encodings supply order information; they do not guarantee reliable extrapolation to arbitrary lengths. The older lecture omits some full-block details: retain the feed-forward sublayer, residual connections and normalisation shown in the assigned paper.
EXAMPLE:: Equal allowed scores give equal softmax weights. With two scalar values \(v_1=2,v_2=6\):

\[\alpha=[0.5,0.5],\qquad
z=\sum_i\alpha_i v_i=0.5(2)+0.5(6)=4.\]

If the second position is unavailable future information, mask it before softmax:

\[\alpha_{\text{masked}}=[1,0],\qquad z_{\text{masked}}=2.\]

The mask changes which evidence can affect the output; it is not merely formatting.
EXPLANATION:: The toy example avoids matrix complexity while showing the effect of a causal boundary. Real attention uses vector values and many positions and heads. A high attention weight is not, by itself, a complete causal explanation of a model's answer.
PITFALL:: A system described as streaming may still use substantial lookahead or wait for a full chunk. Ask how much future context each prediction needs and include that delay in latency accounting.
EXERCISE:: With equal scores and scalar values [1,4,7], calculate unmasked attention. Then calculate attention at the middle position under a causal mask. Explain the result if a fourth padded position is mistakenly included with value 100 and equal score.
SOLUTION:: Unmasked output is four. At the middle position only [1,4] is available, so output is 2.5. Incorrectly including the padded value gives (1+4+7+100)/4=28 when all four are allowed. Padding is not harmless if the mask permits it to influence the computation.
CHALLENGE:: Draft an input contract for batched speech attention containing clips of unequal lengths. Specify axis meanings, length information, padding and causal/lookahead policy. Identify one testable invariant for each mask. For a separate numeric check, take \(d_k=1\), query \(q=1\), keys \(k_1=0,k_2=\ln2\) and scalar values 3 and 9. Compute scaled scores, softmax weights and the output, then mask the second key.

Changing only padded values must not change valid outputs under a correct padding mask. Under a causal policy, changing unavailable future positions must not alter an earlier output. These are deterministic contract ideas, not instructions to run a model here. With \(\sqrt{d_k}=1\), scores are \([0,\ln2]\); exponentials are \([1,2]\), weights \([1/3,2/3]\), and output \(1+6=7\). QUESTION:: What does a causal attention mask enforce?
CORRECT:: A position cannot use later positions that the stated policy makes unavailable.
WRONG1:: Every token must attend equally to every other token.
WRONG2:: Attention weights prove a model's answer is correct.
FEEDBACK:: A mask restricts information flow. Correct masking does not establish language understanding or factual accuracy.

ID:: V21
BRIDGE:: V09 supplies conditional probability, V16 features and V20 dataset structure. Classical speech recognition introduces alignment explicitly before modern losses hide it inside training. Work with the tiny state model; no recogniser is installed.
CONCEPT:: A recording has many short acoustic frames, while its transcript has a much shorter sequence of words or sounds. ASR must connect the two. A hidden Markov model (HMM) describes a sequence of states you cannot observe directly and how those states could produce the observations. It gives you a small, explicit model for studying alignment and decoding.
MECHANISM:: An HMM uses initial-state probabilities, transition probabilities between states and observation likelihoods conditioned on state. Under its stated independence assumptions, the probability of a particular state/observation path is a product of these terms. Viterbi decoding finds the most probable state path; summing over paths answers a different question.
TEACHING:: The hidden states are a model, not a direct measurement of anatomy or meaning. A state might represent part of a phone or another modelling unit. Self-transitions allow it to occupy multiple frames. Connections constrain possible sequences, while emissions relate states to observed features.

Products of many small probabilities become tiny. Logarithms turn products into sums and help numerical handling. Dynamic programming avoids enumerating every path by retaining the best partial score per state at each time. The recurrence works because the model specifies which past information is sufficient.

An acoustic path is not yet a complete account of language. Pronunciation and language constraints may participate in decoding. Scores and assumptions must be documented; changing a language-model weight can alter a transcript without changing the audio. Classical models also simplify dependencies that real speech exhibits.

Here is an actual Viterbi update. Start probabilities are A:0.6 and B:0.4. Transition probabilities are A→A:0.7, A→B:0.3, B→A:0.4, B→B:0.6. For observation one, emissions are A:0.5 and B:0.1; best initial joint scores are therefore A:0.30 and B:0.04. For observation two, emissions are A:0.1 and B:0.8.

To reach A at time two, compare \(0.30\times0.7\times0.1=0.021\) from A with \(0.04\times0.4\times0.1=0.0016\) from B. Keep 0.021 and a backpointer to A. To reach B, compare \(0.30\times0.3\times0.8=0.072\) with \(0.04\times0.6\times0.8=0.0192\). Keep 0.072 and a backpointer to A. The best final path is A→B. You retained one score per ending state, not just the globally best state at the previous time.

The recurrence is \(D_t(s)=e_s(o_t)\max_r\{D_{t-1}(r)a_{rs}\}\), where \(D_t(s)\) is the best partial joint score ending in state \(s\), \(a_{rs}\) is a transition probability and \(e_s(o_t)\) is an emission likelihood. In log space replace multiplication by addition; impossible probabilities correspond to negative infinity, not log(0) evaluated as an ordinary number. A forward algorithm sums incoming path scores instead of maximising them. These are different objectives, which prepares the best-path versus summed-transcript distinction in V22.

In the discrete toy model, an emission value can be a probability. With continuous acoustic features, a Gaussian emission instead gives a probability density. To obtain a probability, integrate over a region. A density’s height can exceed one because it depends on the measurement units; the height itself is not the probability of one exact observation.

Keep the assumptions separate. A first-order transition rule concerns how the next state depends on earlier states. Conditional independence of observations given states concerns how the observations relate once states are specified. Neither assumption follows automatically from the other.

The decoding objective matters too: summing path scores differs from keeping the best path. Taking negative logarithms turns products into sums and a maximisation into a minimisation. You can retain only the current and previous score layers to save memory, but recovering the winning path still needs backpointers or another recovery method.
EXAMPLE:: Two candidate paths for two observations have these supplied factors:

\[\begin{aligned}
P_A&=0.5\times0.8\times0.6\times0.7=0.168,\\
P_B&=0.5\times0.4\times0.9\times0.8=0.144.
\end{aligned}\]

The factors represent start probability, first observation likelihood, transition and second observation likelihood. Among these two candidates, \(P_A>P_B\). This is a joint-path comparison, not a complete recogniser or a normalised posterior over transcripts.
EXPLANATION:: We have compared two supplied joint path scores, not calculated a normalised posterior over every possible transcript. If several paths map to one transcript, the most likely single path and the highest summed transcript probability can disagree.
PITFALL:: The best alignment path is not necessarily the most probable transcript after summing all its possible alignments. State the decoding objective before interpreting the answer.
EXERCISE:: Change Path B's transition to 1.0 and recalculate its score. Then change its first likelihood to 0.6 as well. Determine when the preferred path switches. Draw a two-state, three-time-step trellis and label what information a dynamic-programming table would retain.

SOLUTION:: With only transition changed, B scores 0.16 and remains below A. With first likelihood 0.6, B scores 0.24 and becomes larger. A Viterbi table stores the best partial score reaching each state at each time, plus backpointers, under the stated model.

The time-two state scores are A:0.021 via A and B:0.072 via A, so the best path ends in B and backtracks to A. The losing candidates are 0.0016 and 0.0192 respectively. With the transition fixed at 1.0 and first likelihood \(e\), B scores \(0.5e\cdot1.0\cdot0.8=0.4e\). It ties A at \(e=0.168/0.4=0.42\), and wins only when \(e>0.42\).

ID:: V22
BRIDGE:: V19 introduced sequence outputs and V21 alignment paths. CTC, connectionist temporal classification, allows learning from sequence labels without a supplied frame-by-frame alignment. Learn its collapse rule carefully before looking at architecture diagrams.
CONCEPT:: Suppose you have a recording and its transcript, but no label saying which word belongs to each audio frame. Connectionist temporal classification (CTC) lets a model learn from that pair. It considers several frame-level label sequences that could produce the same transcript and adds their probabilities. You will first learn how those sequences turn into text.
MECHANISM:: CTC introduces a blank symbol alongside ordinary labels. Its collapse map first merges consecutive repeated labels, then removes blanks. Paths that collapse to the target contribute to that target's probability. A dynamic-programming computation sums the valid paths under the model's output assumptions.
TEACHING:: Blank is not a space or a spoken pause label. It means the frame contributes no output token under this representation. Adjacent identical output labels require at least one blank between their runs in a standard CTC path.

The order of collapse operations matters. For a path a,a,blank,a, merging adjacent repeats gives a,blank,a; removing blank gives aa. Removing blanks first would incorrectly turn it into one run of a and lose the repeated label.

Greedy decoding chooses the most likely label at each frame and collapses that path. It does not necessarily return the transcript with highest summed probability across all paths. Beam search approximates a richer search; external language constraints change the decoding setup. Record these details when comparing systems.

Check a complete tiny probability calculation. Use two frames, labels a and blank, and independent frame distributions \(P(a)=0.6\), \(P(\mathrm{blank})=0.4\) at each frame. Four paths exist: aa scores 0.36, a_ scores 0.24, _a scores 0.24 and __ scores 0.16. The first three collapse to a, giving \(P(a)=0.84\); the last collapses to the empty transcript, giving 0.16. These sums total one under this toy model. Two output a labels cannot fit into two frames because a separating blank would require a third frame.

CTC's conditional-independence structure is a modelling assumption. It permits efficient dynamic programming over valid alignments, but it is not a statement that real speech frames are independent. Decoder search, language-model scoring and tokenisation can change how the frame outputs become the final transcript. A greedy path may be easy to inspect while still missing the transcript with the greatest summed mass.

The exact single-example training loss is the negative logarithm of the total target probability, not the average of the losses of its individual alignments. With \(B\) as the collapse map and \(p_t(k\mid x)\) the frame-label probability,

\[P(y\mid x)=\sum_{\pi:B(\pi)=y}\prod_{t=1}^{T}p_t(\pi_t\mid x),\qquad \mathcal L_{\mathrm{CTC}}=-\log P(y\mid x).\]

For the two-frame toy table above, the loss for target a is \(-\log(0.84)\approx0.1744\), using the natural logarithm. Averaging the three path losses is a different calculation. Conditional independence is a specified factorisation given the input; deterministic network computation alone does not prove arbitrary random variables independent. An encoder can use extensive audio context while the CTC output-path probability still uses this factorisation.

To compute the sum without listing every path, insert blanks before, between and after the target's \(U\) labels, giving \(S=2U+1\) positions. Number them from one. The forward value \(\alpha_t(s)\) sums paths reaching position \(s\) at time \(t\). Initialise only the first blank and first target-label positions with their first-frame probabilities; all other positions start at zero. At later frames, add incoming values from the same position and the previous position. Also add the value from two positions earlier only when the destination is a nonblank label different from that earlier label. Multiply that incoming sum by the current frame's destination-label probability. Out-of-range positions contribute zero. Sum the final target-label and trailing-blank positions at time \(T\); ending only on the blank would lose valid paths.

For target a, the extended positions are blank, a, blank. Frame one has forward values \((0.4,0.6,0)\). Frame two has \((0.16,0.6,0.24)\): the middle value is \((0.4+0.6)\times0.6\), and the last is \((0.6+0)\times0.4\). The target total is \(0.6+0.24=0.84\), agreeing with direct enumeration. A target needs at least one frame per label plus an extra frame for each adjacent repeated pair; otherwise it has no valid CTC path. Real implementations handle underflow using log-space or appropriate scaling. The blank identifies no output label, not a universal silence annotation; padding and blank conventions depend on the particular tokenizer and implementation.
EXAMPLE:: Use _ for CTC blank.
Path: b b _ o o _ o k k
Merge adjacent repeats: b _ o _ o k
Remove blanks: b o o k → “book”.

Path: b b o o k k
Merge adjacent repeats: b o k
Remove blanks: “bok”.
A missing separating blank changes the repeated output label.
EXPLANATION:: The transcript letters here are illustrative tokens. Real systems may use characters, subwords or other units. CTC's alignment treatment does not itself define tokenisation, language coverage or whether a particular model operates causally.
PITFALL:: Do not describe CTC as merely deleting duplicates and blanks in any order. The map is precise, and the training objective sums valid paths rather than training only on a guessed alignment.
EXERCISE:: Collapse these paths by hand: a,a,_,a; _,c,c,_,a,t,t; l,l,e,e,t,t,_,t,e,r. Show both intermediate operations. Then construct one path that collapses to “see” and another that collapses to “se”.

CHALLENGE:: Transcript A has valid alignment probabilities 0.15 and 0.14; B has one at 0.25. Explain why a best-path decoder could prefer B while a summed-transcript calculation prefers A. Add one reason a better CTC score alone would not prove a better voice assistant.
CHALLENGE_SOLUTION:: B has the largest individual path, while A totals 0.29. Best-path and marginal objectives differ. Assistant usefulness also depends on semantic errors, timing, permissions, accessibility and downstream actions. A transcript score cannot establish those system properties.
QUESTION:: What is the correct CTC collapse order?
CORRECT:: Merge consecutive repeats first, then remove blank symbols.
WRONG1:: Remove blanks first, then merge every repeated label anywhere.
WRONG2:: Delete all repeated letters from the intended transcript.
FEEDBACK:: Adjacent repetition and blank separation encode alignment. Reversing the operations changes which transcript a path represents.

BRIDGE:: V19 supplies attention and V22 supplies alignment intuition. Encoder–decoder recognition uses a different output model from ordinary CTC. Read the architecture and training-data sections of the assigned Whisper paper; no model download or inference is required here.
CONCEPT:: An encoder–decoder ASR model first turns audio into a representation, then predicts text one token at a time using that representation and earlier tokens. Its knowledge of language can help when the sound is ambiguous. It can also produce a plausible sentence that the recording does not support. BRIDGE:: V19 introduced learned representations, V20 dataset governance and V22 CTC. Self-supervised learning uses structure within input data to define a learning signal. It still needs an explicit objective, data rights and careful downstream validation.
CONCEPT:: Self-supervised learning lets a speech model learn patterns from audio without needing a human transcript for every training example. You still need suitable languages, speakers, permissions and labels for the claim you want to test.
MECHANISM:: In wav2vec 2.0, a feature encoder processes waveform input, masked latent spans create a prediction task, and contextual representations are trained with a contrastive objective involving quantised targets. TEACHING:: Separate pretraining from adaptation. A model may have heard many hours of audio but still need labelled examples for a particular output vocabulary, language or deployment condition. The presence of unlabelled data does not establish that the learned features support every intended task equally well.

A quantizer maps a continuous feature vector to a choice from a finite set of representations. A codebook is a learned table of candidate vectors. In wav2vec 2.0, the quantizer selects an entry from each of several codebooks and combines them to form a target representation. These targets belong to the learning objective; they are not transcript words.

Keep the two branches distinct: the Transformer receives continuous latent features with selected spans masked; the quantizer builds targets from the unmasked latent features. Quantized targets are not the Transformer input. The contrastive objective makes the correct target more similar to its contextual vector relative to negatives; the diversity term discourages collapse to a few codebook choices.

Masking asks the contextual network to use surrounding information to distinguish appropriate targets. It does not mean the model literally fills in every missing waveform sample. Targets, time resolution and objective details matter; read them rather than treating self-supervision as one universal algorithm.

For multilingual work, count representation and labels separately. A language can be absent, scarce or mismatched in accent, device or domain. Adaptation may improve one group while harming another. Define the target population and comparisons before making a general multilingual claim, and preserve speaker/session boundaries throughout.

Connect this learning task to V19. An encoder turns pieces of a waveform into internal vectors, called latent vectors. Some positions are masked before the contextual network sees them. The model must use the available context to distinguish the correct quantised target from distractors; this is the contrastive objective in wav2vec 2.0.

Softmax gives the correct candidate probability 0.75, with negative log-probability about 0.288. This illustrates the arithmetic. It is not the full paper’s training objective or an instruction to train a model.

CONCEPT:: To measure recognition errors, compare a recogniser’s transcript with a reference transcript using a stated set of rules. MECHANISM:: Word error rate is \(\mathrm{WER}=(S+D+I)/N\), where \(S,D,I\) are substitutions, deletions and insertions from a minimum-edit alignment, and \(N\) is the reference-word count. Corpus WER normally sums errors and reference words before dividing. An unweighted mean of utterance WERs answers a different question.
TEACHING:: Define tokenisation and normalisation first. Lowercasing, punctuation removal, number expansion and language-specific word boundaries can change the score. Inspect consequences alongside counts. Confusing “can” with “cannot” can matter more than a stylistic punctuation difference. A low average can conceal serious errors in names, quantities or a particular speaker group. Scores must connect to the product task without replacing faithful reference comparison with subjective tidying.

A difference from a tiny group is a reason to investigate, not proof of a universal population characteristic. System errors should prompt design improvements and accessible alternatives rather than blaming speakers.

The optional two-minute CMU excerpt builds on V22. First ask, “Which single frame-level path has the largest probability?” With fixed independent frame probabilities and no extra sequence constraints, choosing the largest probability at each frame does maximise that path’s product.

Now ask a different question: “Which transcript has the largest total probability?” Several paths can collapse to the same transcript, so you must add their probabilities. The best single path can therefore lose to another transcript with more total probability across its paths.

CTC prefix beam search approximates this second search. It groups probability for compatible transcript prefixes and separately tracks paths ending in blank and nonblank. Keeping a limited beam does not guarantee the global optimum, and it is not simply choosing the top few symbols at each frame. Changing the decoder can change the words and WER even when the acoustic network stays the same. Record that setting; this lesson requires no decoder implementation or model run.

BRIDGE:: V14 introduced source/filter reasoning, V16 convolution and V25 comparison limits. Audio enhancement can improve some signals while damaging others. Use equations and supplied synthetic values; do not process a person's recordings.
CONCEPT:: Several audio tasks deal with unwanted sound, but they solve different problems. Enhancement tries to improve a target signal. Separation tries to recover individual sources from a mixture. Echo cancellation tries to remove sound from the system’s own playback when it returns to the microphone. Beamforming combines microphone signals to favour a direction.
MECHANISM:: A simple mixture is \(x=s+n\), with desired speech \(s\) and interference \(n\). An estimate \(\widehat s\) has residual error \(\widehat s-s\). Multiple microphones observe differently delayed and filtered mixtures; alignment and weighting can reinforce a target direction, subject to room and geometry assumptions.
TEACHING:: Define the target before saying audio is cleaner. Removing all sound gives perfect silence but destroys speech. A meaningful comparison must account for distortion and task consequences, not only lower background energy. Recognition may improve or worsen after enhancement, depending on the recogniser and conditions.

Echo differs from arbitrary noise because a system often has a reference for its own playback. The acoustic path adds delay and filtering. If those change, cancellation needs to track them. A user talking while the agent speaks creates double-talk; suppressing everything during playback would also suppress the user's interruption.

Multi-microphone processing needs synchronised channels and geometry assumptions. A delay error can attenuate rather than reinforce the target. More microphones do not automatically help if channels are misaligned, devices drift or the deployment differs from the tested room.

In a two-microphone delay-and-sum toy model, suppose the same target pulse arrives one sample later on channel 2. Align channels by shifting that channel one sample earlier, then average matching time positions. With channel 1 [1,0,−1] and the aligned part of channel 2 [1,0,−1], the average preserves [1,0,−1]. Without alignment, averaging [1,0,−1] with [0,1,0] gives [0.5,0.5,−0.5], which smears this target. This assumes a known integer delay, synchronised sampling and no noise/reflections; real beamforming needs geometry, fractional delays and more careful design.

An adaptive echo filter uses playback samples to predict the microphone’s echo, subtracts that prediction, then adjusts filter coefficients using the residual and a controlled update rule. A changing room path changes the required coefficients. Independent user speech during double-talk is not an error to erase. This is a conceptual introduction; implementing adaptive algorithms or source-separation training is further study, not part of this lesson’s numeric exercise.

BRIDGE:: V16 supplies filters/features and V29 acoustic-model outputs. A waveform contains many samples per second. Vocoders and neural codecs provide different ways to generate or represent those samples; keep their purpose and interfaces distinct.
CONCEPT:: A vocoder turns an input representation, such as acoustic features, into a waveform. A neural codec has a different job: compress audio and reconstruct it. Some codecs represent audio with discrete tokens. Other models can then learn to generate sequences of those tokens. Keep waveform generation, compression and token generation separate as you compare designs.
MECHANISM:: WaveNet models waveform samples autoregressively in its original formulation, conditioned on prior samples and optional context. A codec encoder maps audio to latent features, quantisation selects finite codebook entries and a decoder reconstructs audio. Multiple residual codebooks can refine the representation, increasing bitrate and potentially fidelity under a specific design.
TEACHING:: Separate generation rate from audible duration. A waveform at 24 kHz contains 24,000 samples per second. A codec can represent a second with a smaller number of frame-level tokens, but the exact rate depends on frame rate, codebooks and vocabulary size. Fewer tokens do not automatically mean lower end-to-end latency.

Compute a nominal token payload before discussing compression. With K codebooks, frame rate F and V entries per codebook, a fixed-length index representation uses \(KF\log_2 V\) bits/second when V is a power of two. Real files may add headers, entropy coding, framing and other overhead.

Reconstruction is not guaranteed identical to the input. A codec designed for perceptual quality can discard detail. Downstream speaker, clinical or forensic analysis may care about details that are not central to perceived naturalness. Review task suitability rather than treating every compressed representation as interchangeable.

A neural codec usually has an encoder, a quantiser and a decoder. The encoder maps waveform frames to continuous latent vectors. The quantiser selects discrete codebook entries; the decoder reconstructs a waveform from those entries. A vocoder maps an acoustic representation such as mel features to waveform; it need not provide a discrete compression interface. A model may combine these responsibilities, so inspect the actual diagram.

Residual vector quantisation represents what earlier codebooks missed. Use a one-dimensional toy latent 2.7: the first codebook {0,2} chooses 2, leaving residual 0.7. A second codebook {0,0.5,1} chooses 0.5, leaving residual 0.2. Reconstruction is 2+0.5=2.5. The two indices describe this approximation; adding codebooks can change rate, compute and reconstruction error. This small scalar example illustrates the operation and does not describe EnCodec's actual learned vectors or settings.

Quality objectives are distinct. Waveform distance, spectral distance, adversarial training and perceptual judgements emphasise different properties. A plausible reconstruction can still change a name, speaker cue or low-energy sound relevant to a downstream task. Read the codec paper's representation, objectives and experiments separately from its compression headline.

The assigned video explains SemantiCodec. The main compression paper on Watch & read explains EnCodec. Keep the two designs separate as you read their diagrams.

SemantiCodec’s paper describes three main parts: an AudioMAE-based semantic encoder quantised with k-means, an acoustic encoder that carries further detail and a diffusion-based decoder. Automatic captions repeatedly misspell these names, so use the paper’s diagram when checking the terminology.

AudioMAE learns by reconstructing masked audio representations. A diffusion decoder learns, at a high level, to remove added noise while using a representation as guidance. That does not mean it recreates every original waveform sample exactly. This introduction helps you read the diagram; implementing a diffusion sampler is further study.

A GAN uses a generator and a discriminator during training. The discriminator’s training role does not make it the codec’s runtime encoder. Also separate the codec result from a later language-model claim: richer semantic representations do not by themselves prove better downstream results. The speaker leaves that question open.

R&=FK\log_2 V\\

BRIDGE:: V04 supplied errors/tests, V05 reproducibility and V32 dialogue state. An asynchronous operation may finish later than one started after it. This lesson teaches event reasoning before introducing any networking implementation.
CONCEPT:: In a streaming system, new information can arrive while earlier work is still running. Concurrency lets work overlap. Distinguish occurrence time from arrival time. A network message can arrive late or out of order. Use sequence numbers and a documented policy rather than assuming callback order equals conversational order. Handle duplicate events explicitly, especially around state-changing tools.

Queues decouple producers and consumers. If audio arrives faster than it can be processed, an unbounded queue accumulates delay and memory. Choose a bounded capacity and a policy: apply backpressure, drop only safely discardable work or terminate with a clear fallback. Never silently drop consequential confirmations.

Cancellation is not time travel. Audio already played cannot be unheard; a database write already committed cannot be cancelled by aborting a text stream. Track separately the model generation, queued audio, audible playback and tool transaction. Each needs the appropriate termination or recovery rule.

Cancellation cleanup has an owner. Suppose a response task owns an unplayed-audio queue and a consumer owns playback. Cancelling generation only stops its future work; the consumer must also reject stale generation IDs and flush the obsolete unplayed queue. A finally block can release resources even if an awaited operation is cancelled. Re-raise CancelledError after cleanup when catching it; swallowing cancellation can break structured-concurrency assumptions. V04 warned against hiding errors with broad handlers; cancellation adds a separate lifecycle that needs explicit handling.

BRIDGE:: V12 introduced audio formats and V34 event queues. This lesson introduces the networking terms used by real-time systems. It is a conceptual comparison; no microphone permission, telephone call or network service is launched.
CONCEPT:: Your app needs to move audio and control messages between devices or services. This job is called transport. WebSockets, WebRTC and telephone protocols solve different parts of it. Before choosing one, ask what it carries, how the connection starts, which delays are acceptable and what happens when data is late or missing.
MECHANISM:: IP addresses identify network endpoints; ports distinguish services. DNS maps names to addresses. TEACHING:: NAT (network address translation) lets a network rewrite addressing information, commonly so devices share an outward-facing address. Separate media from signalling. Signalling exchanges information needed to establish or control a session. RTP carries real-time media in many systems; SIP handles session signalling in many telephony deployments. Reliability has timing trade-offs. Waiting for a lost byte in an ordered stream can delay later bytes. Real-time media may prefer a controlled loss-concealment policy over waiting too long. A jitter buffer smooths variable arrival times by adding some delay. It cannot make an unstable connection free of trade-offs.

WebRTC's connectivity tools address NAT and network paths; TURN can relay traffic when a direct path is unavailable. Encryption in transit does not stop an authorised receiving server from seeing decoded content. State where media terminates, who can access it and which retention policy applies.

Network bridge: an IP address identifies a network endpoint, and a port identifies a receiving service on that endpoint. DNS resolves a name to addressing information; it does not authenticate the service's application user. TCP supplies an ordered byte stream with retransmission. UDP supplies datagrams without that same delivery/order guarantee. TLS protects an authenticated transport channel; application account permissions still require their own checks.

WebSocket upgrades an HTTP connection to a bidirectional message channel and normally inherits TCP ordering. WebRTC is a collection of media, security and connectivity mechanisms, not just a browser microphone call. ICE coordinates connectivity candidates; STUN can help discover mapped addresses; TURN relays traffic when a direct route is unsuitable. A relay adds an operational dependency and cost even when media encryption is preserved. SIP messages organise sessions in many phone systems, while RTP timestamps/sequence numbers support media delivery. BRIDGE:: V09 introduced distributions and V34–V36 asynchronous pipelines. Latency is elapsed time between explicitly defined events. Use the supplied trace for arithmetic; do not start a model benchmark or live timing run.
CONCEPT:: You hear a reply only after several steps: detecting the end of your turn, recognising speech, deciding what to do, using any required tools, generating audio and playing it. TEACHING:: A critical path is the longest dependency chain that must finish before the stated result can occur. If two independent preparation steps start together and take 40 ms and 70 ms, both are ready after 70 ms, not 110 ms. If a required 30 ms step then follows them, the chain takes 100 ms. For recorded response-or-timeout endpoint durations [100,200,300,400,5000] ms, with the last marked timeout, p50 is rank 3 = 300 ms and p95 is rank 5 = 5000 ms. Do not mix endpoint definitions without labels.

Queue wait is execution-start minus enqueue time; service time is finish minus execution-start. A request enqueued at 100 ms, started at 160 ms and finished at 250 ms waits 60 ms and executes for 90 ms. Its queue-plus-service span is 150 ms. A trace makes these different remedies visible.

\Delta t_{\text{endpoint}}&=1250-1000=250\ \mathrm{ms},\\

\end{aligned}\]
